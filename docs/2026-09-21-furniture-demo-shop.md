# Отчёт: демонстрационный интернет-магазин мебели ORNATA

Дата: 21.09.2026

---

## 1. Задание

Разработать с нуля полноценный современный интернет-магазин мебели: рабочий
demo, а не макет. Требовалось: responsive-витрина и мобильная версия, backend и
API, база данных, каталог на 250–300 товаров по 16 категориям (окна не
добавлять), корзина, оформление заказа, личный кабинет, избранное, сравнение,
поиск с автодополнением, фильтры, админ-панель с реальным управлением товарами
и заказами, DEMO-данные, DEMO-пользователи, DEMO-заказы, рабочий DEMO-checkout,
отдельные сценарии для кухонь (калькулятор + заявка) и дверей (конфигуратор с
пересчётом цены), три языка (hy/ru/en), валюта AMD, ориентация на Армению,
контентные и юридические страницы, SEO, безопасность (хеширование паролей,
RBAC, rate limiting, серверная проверка цены), тесты, production-сборка,
запуск одной командой и подробный README.

Полный текст задания — в истории задачи; здесь перечислены проверяемые пункты.

## 3. Что сделано

### 3.1 Стек и инфраструктура

- Next.js 16 (App Router, React 19 Server Components), TypeScript strict
  (`noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`).
- PostgreSQL 16 + Prisma 6: `apps/shop/prisma/schema.prisma`, миграция
  `20260921184903_init`, seed `apps/shop/prisma/seed.ts`.
- Tailwind CSS v4 + собственная дизайн-система на токенах
  (`apps/shop/src/app/globals.css`).
- Запуск одной командой: `npm run setup` (`apps/shop/scripts/setup.ts`) —
  создаёт `.env`, генерирует уникальный `AUTH_SECRET`, применяет миграции,
  наполняет базу. Локальная БД — `apps/shop/docker-compose.yml`.
- Деплой: `apps/shop/Dockerfile` (multi-stage, миграции на старте,
  seed по флагу `SEED_ON_START=1`), профиль `app` в compose.

### 3.6 Безопасность

- Пароли — argon2id (memoryCost 19 MiB, timeCost 2).
- Сессия — подписанный HS256 JWT в HttpOnly/SameSite=Lax cookie; в production
  приложение отказывается подписывать сессии значением-заглушкой `AUTH_SECRET`.
- RBAC: `requireAdmin` в layout админки (ни одна страница не может забыть
  проверку) и `requireAdminApi` во всех `/api/admin/*`.
- Все входящие данные проходят zod-схемы (`src/lib/validation.ts`).
- Rate limiting на логине, регистрации, OTP, заявках, подписке, отзывах,
  расчёте корзины и checkout. Лимит логина настраивается `AUTH_RATE_LIMIT_MAX`
  (по умолчанию 10 за 5 минут).
- **Цену заказа считает только сервер**: клиент передаёт id товара, количество и
  ключи опций; `computeQuote` пересчитывает всё заново из каталога, а checkout
  делает это ещё раз перед записью заказа. В API нет ни одного поля с ценой.
- Заказы и адреса читаются с фильтром по `userId` — чужой заказ по номеру не
  открывается (проверено тестом).

## 4. Что НЕ сделано

### 4.1 Сознательно вне объёма

- **Админка только на русском.** Витрина полностью трёхъязычная, админка —
  инструмент оператора, переводить её не стал. Это решение, а не упущение, но
  если демо показывают армяноязычному партнёру как рабочее место — язык
  придётся добавить.
- **Тёмная тема** не сделана (в задании не было).
- **Конструктор кухни как CAD** не делался — в задании прямо разрешено
  ограничиться формой и оценкой.
- **Список вариантов товара не влияет на остаток по SKU.** Варианты — это
  надбавки к цене, а не отдельные складские позиции. Для реального магазина с
  учётом остатков по цвету потребуется матрица SKU.
- **Отзывы не модерируются**: авторизованный покупатель публикует отзыв сразу
  (поле `isPublished` в модели есть, интерфейса модерации нет).
- **Редактирование изображений в админке.** Картинки генерируются из категории
  и цвета; загрузки файлов нет — для реального магазина это первый пункт
  доработки.

### 4.2 Собственные ошибки по ходу работы

Перечисляю честно — это то, ради чего отчёт и читают.

1. **Сломал все Tailwind-утилиты цвета и не заметил бы без скриншота.**
   Базовые сбросы (`a { color: inherit }`) я написал вне слоёв, а нелayered CSS
   в каскаде сильнее любого `@layer utilities`. В результате текст на кнопке
   hero был цвета фона — кнопка выглядела пустой. Нашёл, только сняв скриншот
   главной. Исправлено обёрткой сбросов в `@layer base`.
2. **Админ-форма требовала заполнить все три языка.** Схема валидации требовала
   `name` минимум 3 символа в каждой переданной локали, а форма всегда
   отправляла три. Создать товар, заполнив только русский, было невозможно.
   Нашёл E2E-тестом. Исправлено: форма отправляет только заполненные локали.
3. **Товар без перевода показывал артикул вместо названия.** Прямое следствие
   пункта 2: запросы брали перевод строго по текущей локали. Исправлено —
   теперь fallback на русский.
4. **Двойное сохранение создавало дубль товара.** После создания форма
   переходила на страницу редактирования асинхронно, и второе «Сохранить» до
   перехода делало ещё один POST. Исправлено: форма подхватывает id сразу.
5. **Собственный rate limiter блокировал E2E-прогон** (429 на логине). Сначала
   это выглядело как баг тестов. Исправил правильно: лимит вынесен в
   `AUTH_RATE_LIMIT_MAX`, production-значение не ослаблено, повышает его только
   тестовый сервер.
6. **Защита `AUTH_SECRET` сделала production-сборку непригодной для показа.**
   Проверка «в production нельзя подписывать сессии демо-секретом» сработала
   при `npm start` локально — вход перестал работать. Исправлено на уровне
   причины: `npm run setup` генерирует уникальный секрет при установке.
7. **Первая версия генератора изображений давала брак.** Угловой диван
   разваливался на две несвязанные части, «деталь» кадрировала пустую стену,
   кухонный остров не читался, а дверь в «ракурсе» выглядела падающей. Всё
   чинилось по скриншотам, в три прохода.
8. **Тесты ловили момент стриминга.** Next на короткое время держит поздние
   HTML-чанки в скрытом контейнере, из-за чего одна и та же форма существует в
   DOM дважды и строгий режим Playwright падает. Час ушёл на то, чтобы понять,
   что это не баг приложения. Решено хелпером `settle()` — причём первая его
   версия ждала исчезновения самого контейнера, который Next не удаляет
   никогда, и добавляла по 30 секунд к каждому тесту; исправлено на ожидание
   реального условия.
9. **Дважды запустил E2E параллельно** против одной базы: прогоны разлогинивали
   друг друга, и я почти час разбирал «плавающие» падения авторизации, которых
   в приложении не было. Отдельно наступил на `pkill -f "playwright test"` —
   шаблон совпал с моей же командой, и она убила сама себя вместе с правками,
   которые должна была применить.

### 4.3 Заблокировано внешними условиями

## 6. Что осталось непроверенным (UNVERIFIED)

- **Публичный деплой** — Dockerfile и compose написаны, но образ не собирался и
  на Railway/Render/Vercel не разворачивался.
- **Реальные браузеры кроме Chromium.** Тесты и скриншоты сняты только в
  Chromium (WebKit/Firefox в окружении не установлены). Safari и Firefox не
  проверялись вообще.
- **Реальные устройства.** Мобильная версия проверена эмуляцией iPhone 13 в
  Chromium, на живом телефоне не открывалась.
- **Нагрузка.** Производительность под нагрузкой не измерялась; Lighthouse не
  запускался.
- **Доступность (a11y).** Есть скип-ссылка, фокус-стили, aria-подписи и
  touch-таргеты 44+ px, но аудита скринридером не было.
- **Импорт больших файлов.** Импорт проверен на 2 строках; лимит 500 строк
  заложен, но на больших объёмах не гонялся.
- **Параллельная работа нескольких админов** (конкурентные изменения статусов).
- **Восстановление пароля** не реализовано и, соответственно, не проверено.

## 8. Вопросы владельцу

1. **Название и бренд.** Сейчас временный `ORNATA` — всё вынесено в
   `src/config/brand.ts` и переменные `NEXT_PUBLIC_BRAND_*`. Нужно ли подставить
   реальное название и палитру?
2. **Язык админки.** Оставляем русский или переводим на армянский/английский?
3. **Публичный деплой.** Нужен ли развёрнутый стенд с адресом? Если да —
   потребуется доступ к аккаунту (Railway/Render/Vercel) и домен.
4. **Эквайринг.** Какой провайдер планируется — от этого зависит модель
   оплаты (redirect или виджет) и схема webhook.
5. **Остатки по вариантам.** Нужен ли учёт склада в разрезе цвет/размер? Это
   единственное изменение, которое затрагивает схему данных.
