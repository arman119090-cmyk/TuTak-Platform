# Astra — обязательные правила работы

1. Минимум слов, максимум полезной информации.
2. Приоритет лимита: работа → доказательства → тесты → проверка результата → краткий отчёт.
3. Не повторять задачу, историю и уже подтверждённые факты.
4. Не писать длинные вступления, рассуждения и промежуточные отчёты.
5. Использовать минимально достаточный контекст; расширять только при необходимости.
6. Ссылаться на file/path/SHA/test вместо копирования больших фрагментов.
7. Не повторять дорогие проверки, если результат уже доказан на том же commit и не затронут изменениями.
8. Экономия лимита никогда не оправдывает пропуск обязательных тестов, security-check, доказательства root cause или проверки результата.
9. Итоговый отчёт: что сделано; доказательство; тесты; commit SHA; блокер/следующий шаг. Только необходимое.
10. Технические детали оставлять компактно в GitHub; Simon объясняет Арману результат.

Формула: correctness → safety → evidence → quality → экономия лимита → краткость текста.
