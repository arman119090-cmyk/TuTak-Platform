## 3. Установка

Ставится **поверх существующего приложения**: package id `am.tutak.app` во
всех окружениях, подпись та же (ключ хранится в EAS). Это обновление, а не
переустановка — данные приложения сохраняются.

**Удалять приложение и чистить его данные не нужно.** Если это всё же
понадобится, последствия такие: стирается сохранённая сессия, и входить
придётся заново — то есть снова через SMS-код.

Android спросит разрешение установить приложение из этого источника — это
нормально для файла не из Play.

После установки приложение называется **TuTak (preview)**.

## 4. Что сделать на телефоне

Сбой воспроизводится на **экране входа** — там, где снято прошлое видео. Его и
повторяем.

1. Открыть приложение — экран «С возвращением» с полями **Номер телефона** и
   **Пароль**.
2. Нажать **CLEAR** в чёрной панели внизу.
3. Нажать на поле **Номер телефона** и дождаться, пока клавиатура мигнёт.
   Повторить 2–3 раза, **не нажимая CLEAR между попытками**.
4. Нажать **EXPORT** и прислать журнал.

Если несложно — тем же способом снять второй журнал на экране «Создать
аккаунт» (поля Phone number и Referral code). Совпадает ли рисунок на двух
экранах — это отдельная улика.

### Сведения о телефоне (без них журнал читается наполовину)

* модель — Galaxy Z Fold какого поколения;
* версия Android и One UI;
* название клавиатуры (Samsung Keyboard, Gboard, другая);
* **сложен или раскрыт** в момент сбоя;
* ориентация (портрет / ландшафт);
* включён ли режим совместимости для приложения;
* тот же ли это телефон и то же ли состояние, что на прошлом видео.

Отдельно ценно повторить то же самое на **сложенном** телефоне: другой журнал
там сам по себе указывал бы на режим совместимости раскрытого экрана.

## 6. Что журнал теперь умеет говорить

Прошлый журнал показал, что дефект — **не «клавиатура закрывается»**, а
самопроизвольная миграция фокуса `phone → password → phone → none`, после
которой клавиатура закрывается уже законно. Осталось выяснить одно: **кто
переводит фокус на «Пароль»**.

Новые строки отвечают ровно на это:

| Строка | Что означает |
|---|---|
| `trace focus-commands armed` | инструмент встал (если вместо неё `UNAVAILABLE` — не встал, и это видно, а не молчит) |
| `REQ focus password src=…` | **фокус запросил JavaScript**, и `src` называет вызывающего |
| `focus password` **без** предшествующей `REQ` | **никто не запрашивал** — фокус перевёл Android / автозаполнение / IME |
| `REQ blur phone src=…` | что-то программно сняло фокус (например, `ScrollView` или `Keyboard.dismiss`) |
| `touch password` | по полю действительно попали пальцем |
| `focus password` без `touch password` | касания не было — это не пользователь |
| `t=123` в строках focus/blur | номер native-view; если у одного поля он меняется — native-view пересоздан без remount |

Остальное — как было: `run`, `mount App #n`, `mount Login #n`,
`mount field:… #n @id`, `kbShow/kbHide … on=… kbd=…`, `win/scr`, `appState`.

Три вещи держатся раздельно намеренно:

1. **Рамка на поле — не доказательство фокуса.** Это состояние React; именно
   её видно на видео.
2. **`isFocused()` — не запрос к Android.** Это учёт RN по тем событиям, о
   которых ему сообщили.
3. **`REQ` — это запрос, а не отчёт.** RN держит учёт (`focusInput`, из
   `onFocus`) и команды (`focusTextInput`, через который идёт любой
   `ref.focus()`) в разных функциях. Перехвачены **только команды** — иначе
   вариант B записывался бы как вариант A, и журнал отвечал бы не на тот
   вопрос.

Инструмент ничего не меняет: команды вызываются дальше как есть, касания не
перехватываются, перехват ставится только в диагностической сборке, а
отсутствие внутреннего модуля RN оставляет приложение прежним.

## 7. Дальше

Получаем журнал → по наличию или отсутствию `REQ` перед `focus password`
называем инициатора → минимальная правка под доказанную причину → повторная
проверка на том же телефоне → regression tests.

**До этого проблема исправленной не объявляется.**

Ничего из введённого в журнал не попадает: только идентификаторы полей,
размеры, счётчики, номера native-view и факт монтирования. На это есть тест.
