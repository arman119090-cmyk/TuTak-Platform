## 3. Установка

Ставится **поверх существующего приложения**: package id `am.tutak.app` во
всех окружениях, подпись та же (ключ хранится в EAS). Это обновление, а не
переустановка — данные приложения сохраняются.

**Удалять приложение и чистить его данные не нужно.** Если это всё же
понадобится, последствия такие: стирается сохранённая сессия, и входить
придётся заново — то есть снова через SMS-код.

Android спросит разрешение установить приложение из этого источника — это
нормально для файла не из Play.

После установки приложение называется **TuTak (preview)**.

## 4. Что сделать на телефоне

1. Открыть приложение → «Создать аккаунт» (экран **Create your account** с
   полями Phone number и Referral code).
2. Нажать **CLEAR** в чёрной панели внизу.
3. Воспроизвести сбой так же, как на видео: нажать на поле, дождаться мигания
   клавиатуры. Повторить 2–3 раза, **не нажимая CLEAR между попытками**.
4. Нажать **EXPORT** — откроется системное меню «Поделиться». Отправить
   журнал любым способом.

Если EXPORT почему-то не сработает — сфотографировать панель: в заголовке
есть и SHA сборки, и идентификатор запуска.

Полезно, если несложно: проделать это дважды — сначала нажав на **Phone
number**, потом на **Referral code**. Какое из двух полей ведёт себя иначе —
это уже половина ответа.

### Сведения о телефоне (без них журнал читается наполовину)

* модель — Galaxy Z Fold какого поколения;
* версия Android и One UI;
* название клавиатуры (Samsung Keyboard, Gboard, другая);
* **сложен или раскрыт** в момент сбоя;
* ориентация (портрет / ландшафт);
* включён ли режим совместимости для приложения;
* тот же ли это телефон и то же ли состояние, что на прошлом видео.

Отдельно ценно повторить то же самое на **сложенном** телефоне: другой журнал
там сам по себе указывал бы на режим совместимости раскрытого экрана.

## 6. Что журнал теперь умеет говорить

| Строка | Что различает |
|---|---|
| `run ABC123` в заголовке | новый id = новый JS-контекст (перезапуск процесса) |
| `mount App #2` при том же run id | перезапуск RN surface — кандидат на пересоздание Activity |
| `mount OtpRegister #2` при `mount App #1` | React пересобрал только экран |
| `mount field:phone #1 @3` / `unmount field:phone @3` | поле заменено, а не перерисовано |
| `focus phone kbd=number-pad` | какое поле и какую клавиатуру оно просит |
| `kbShow h=850 on=referral kbd=default` | **какому полю принадлежала клавиатура** в момент появления |
| `kbHide on=referral kbd=default` | было ли `blur` перед закрытием и держал ли кто-то фокус |
| `kbShow … on=none of=2` | клавиатура на экране, ни один input не считает себя сфокусированным |
| `win WxH scr WxH` | уменьшается ли окно под IME |
| `appState …` | пересоздаваемая Activity не остаётся `active` всё это время |

Три вещи держатся раздельно намеренно:

1. **Рамка на поле — не доказательство фокуса.** Это состояние React; именно
   её видно на видео, и именно её читать нельзя.
2. **`isFocused()` — не запрос к Android.** Публичного API «какая native-view
   держит фокус» в React Native нет. Это учёт RN по тем событиям, о которых
   ему сообщили.
3. **Поэтому расхождения и есть улика.** `on=none of=2` и
   `on=phone+referral kbd=multiple` — это находки, а не пробелы в данных.

Про независимые тесты Симона: они показывают, что на базе `f63b34f`
экземпляры полей и их `keyboardType` не меняются при focus/blur, вводе,
очистке и изменении высоты клавиатуры. Это закрывает JS-сторону вопроса и
согласуется с чтением кода. Native-фокус Android они не проверяют и сценарии
E (пересоздание Activity / перезапуск surface) и F (систе́ма закрывает IME
при сохранённом фокусе) не закрывают — у Jest нет IME. Ровно поэтому ценность
журнала смещена туда, куда он и указал.

## 7. Дальше

Получаем журнал → называем механизм по счётчикам и порядку событий →
минимальная правка под доказанную причину → повторное воспроизведение на том
же телефоне → regression tests.

**До этого проблема исправленной не объявляется.**

Ничего из введённого в журнал не попадает: только идентификаторы полей,
размеры, счётчики и факт монтирования. На это есть тест.
