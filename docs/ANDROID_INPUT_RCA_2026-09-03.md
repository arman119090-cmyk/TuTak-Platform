# EVIDENCE

## Симптом сам исключает два сценария

Клавиатура **появляется**, пусть и на полсекунды. Клавиатуру Android
открывает только когда native `TextInput` получил фокус. Следовательно:

* **A (касание не доходит до TextInput) — исключён.** Дошло.
* **H (касание перехватывает родитель) — исключён.** Не перехвачено.

Это не рассуждение, а прямое следствие наблюдения.

## Исключено поиском по коду

| Сценарий | Что искал | Результат |
|---|---|---|
| **B** — JS снимает фокус | `Keyboard.dismiss`, `.blur()`, `blurOnSubmit`, `.focus()`, `autoFocus` | **ноль совпадений во всём `apps/mobile/src`** |
| **G** — навигация меняет экран | `navigation.reset`, `addListener('focus')`, `useFocusEffect`, `useIsFocused` | **ноль совпадений** |
| **C/D** — remount по смене `key` | `key={` в дереве auth | только списки (`.map`), на пути входа ни одного |
| **H** — перекрытие поля | `pointerEvents` | только маркеры карты, водяные знаки и диагностический оверлей (`box-none`, пропускает касания). На auth-экранах — ничего |
| **I** — исключение и recovery-render | `ErrorBoundary` | `getDerivedStateFromError` ставит `hasError` и **не сбрасывает его**. Ошибка оставила бы экран ошибки навсегда, а не мигание. Native-исключение уронило бы приложение |

## Исключено чтением

**`ThemeProvider`** — возвращает константу `tutakMobileLightTheme`, не читает
размеры, не имеет состояния, влияющего на layout. `navigationTheme` в
`App.tsx` зависит только от неё, значит идентичность объекта стабильна и
`NavigationContainer` не получает новый `theme` при открытии клавиатуры.

**`{user ? <RootNavigator/> : <AuthNavigator/>}`** — переключается только по
`user`. При наборе в форме входа `user` остаётся `null`.

**`TextField`** — обычный `TextInput`, `flex: 1`, ничем не перекрыт,
`importantForAutofill="no"`, `autoComplete="off"` (автозаполнение Android уже
отключено прошлой правкой).

**`KeyboardAwareScroll`** — `KeyboardAvoidingView` удалён ещё в августе;
`keyboardShouldPersistTaps="handled"`; `useKeyboardInset` читает высоту из
события IME, а не из собственного фрейма, поэтому петли layout нет.

## Почему остаются ровно два сценария

Remount `TextInput` (**C**) или `LoginScreen` (**D**) требует либо смены
`key`, либо пересоздания родителя. Ни того, ни другого в JS-дереве нет.
Значит остаются:

* **E — Android пересоздаёт Activity**, React Native surface стартует заново;
* **F — Android закрывает IME**, хотя фокус у поля сохраняется.

Оба — вне JavaScript. Это объясняет две вещи, которые раньше не складывались:
**почему пять правок в JS не помогли** и **почему тот же дефект был в `demo/`**
— у них общий Android-конфиг и одна версия Expo.

## Что известно про конфигурацию

| Параметр | Значение | Откуда |
|---|---|---|
| Expo SDK | 57 | `package.json` |
| React Native | 0.86.2 | `package.json` |
| `orientation` | `portrait` | `app.config.js:235` |
| `softwareKeyboardLayoutMode` | **не задан** → умолчание `resize` → `adjustResize` | поиск по всему проекту: совпадений нет |
| каталог `android/` | отсутствует | манифест генерирует EAS |

Приложение написано в расчёте на edge-to-edge (окно **не** уменьшается,
клавиатура — это inset). Но на раскрытом складном экране в режиме
совместимости Android может дать вместо этого legacy-поведение
`adjustResize`, при котором окно **уменьшается**. Тогда всё, что читает
размер окна, перекладывается прямо под анимирующейся клавиатурой.

Это и есть развилка между E и F. Проверяется одним измерением.

закрытием IME системой — а чинятся они по-разному.

# Как читать журнал — три варианта, три вывода

**Вариант 1 — пересоздание Activity (сценарий E):**
```
mount Login
focus Номер телефона
kbShow h=...
mount Login        ← второй раз
```
Вывод: Android перезапускает Activity при появлении IME. Лечится
конфигурацией Android (`softwareKeyboardLayoutMode`, `configChanges`,
поведение на складных экранах), а не React-кодом.

**Вариант 2 — окно уменьшается (сценарий E, мягкая форма):**
```
focus Номер телефона
kbShow h=850
win 1080x1200 scr 1080x1812   ← высота окна упала, экран стоит
blur  Номер телефона
kbHide
```
Вывод: работает legacy `adjustResize`. Лечится переводом на `pan` или
корректной обработкой inset.

**Вариант 3 — система закрывает IME (сценарий F):**
```
focus Номер телефона
kbShow h=850
kbHide                        ← без blur, без mount, без изменения win
```
Вывод: приложение фокус не роняло; IME закрывает система. Причина в
режиме совместимости складного экрана.

# ЧТО НУЖНО С УСТРОЙСТВА

Ровно одно фото. Диагностическая сборка показывает журнал внизу экрана.

1. Установить, открыть приложение.
2. **Нажать «Clear»** в журнале — чтобы в кадре было одно взаимодействие.
3. Нажать на поле «Номер телефона». Клавиатура мигнёт.
4. **Сфотографировать журнал.**

Достаточно 5–10 строк. По ним причина называется однозначно, без гипотез.

**Второе, необязательное, но ценное:** повторить то же самое на **сложенном**
телефоне (внешний экран). Если там журнал выглядит иначе — это само по себе
доказывает, что причина в режиме совместимости раскрытого экрана.
