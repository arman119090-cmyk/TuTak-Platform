# Аудит 23.09.2026: клиент, партнёр, владелец

Ветка `partner-settlement-transparency` (PR #69, draft). Ничего не мержилось и не
деплоилось. Production, PSP, POS и prepaid не трогались. Реальных платежей и SMS не было.

## Как проверялось

- Сборка и статические проверки. Typecheck по всем 8 пакетам, lint по всему репозиторию.
- Все наборы тестов:
  - API unit;
  - API integration на локальном PostgreSQL 16;
  - partner, admin и mobile (jest).
- Контракты. Каждый вызов из клиентов (mobile, partner, admin) сверен с реальными маршрутами API
  (скрипт по исходникам). Расхождений нет.
- i18n. Сверены все ключи `t('…')` в коде с `en/ru/hy.json`. Отсутствующих ключей 0.
- Доступ. Все маршруты с `partnerId` проверены на наличие guard'а или проверки в обработчике.
- Экраны прочитаны глазами клиента, партнёра и владельца. Проверено, что видит человек при вводе
  с русской или армянской клавиатуры, ночью по Еревану, при ошибке сети и без нужной роли.

## Не исправлено (нужно решение или внешний доступ)

1. **Railway.** С 14:56Z коннектор отвечает «permission denied» на проект TuTak. Аккаунту видна только
   `little-joe-armenia`. Состояние production из сессии проверить нельзя. Нужно заново выдать
   доступ коннектору к проекту TuTak.
2. **Текст SMS** с кодом входа и приглашением в коде английский, но у Viva используется шаблон. Что реально
   получает человек, без реальной отправки проверить нельзя, а реальные SMS отправлять нельзя.
3. **Админка только на английском.** Это рабочий инструмент команды, а не клиента. Переводить её или нет,
   решает владелец.
4. **День сверки считается по UTC.** Так задумано: у провайдера отчёты тоже по UTC. Менять только вместе
   с правилами сверки.
