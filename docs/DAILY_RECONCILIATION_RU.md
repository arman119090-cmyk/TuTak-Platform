# Ежедневная сверка — инструкция на одну страницу

Пункт 27 чек-листа (`READINESS_CHECKLIST_2026-09-21_RU.md`). Кто делает — вписывает владелец
(роль «Secondary approver» или «Primary on-call» из `PILOT_ROLES_RU.md`). Время: каждый рабочий
день до 11:00, за предыдущий день. Ночной прогон делает то же самое автоматически; ручной —
чтобы человек посмотрел результат и расписался.

## 1. Что нужно

- Доступ в Admin-панель с правами на Reconciliation, Ledger, Settlements, Payouts.
- Выписка банка TuTak за предыдущий день (для поступлений от партнёров).
- Когда включат Idram — кабинет Idram за предыдущий день (для маршрута TUTAK_PSP).
- Журнал сверки: таблица в конце этого файла (или её копия в общей папке).

## 2. Шаги (15 минут при отсутствии расхождений)

1. **Admin → Reconciliation.** В поле «Day to reconcile» — вчерашняя дата → Run. Дождаться
   строки в таблице: Day / Result / Findings / Run at.
   - `Result = OK`, findings 0 → записать в журнал «OK», перейти к шагу 2.
   - findings > 0 → **ничего не править**, записать текст findings, сразу эскалировать
     по `RUNBOOK_INCIDENTS_RU.md` §9 (ledger imbalance) — партнёры из findings уже
     заблокированы для выплат автоматически.
2. **Admin → Ledger → accounts.** Сумма всех счетов = 0 (двойная запись). Проверить, что
   `PARTNER_PAYABLE` по каждому активному партнёру совпадает с позицией в
   Admin → Settlements → unsettled/position. Расхождение = finding, шаг 1.
3. **Поступления от партнёров (взыскания).** Для каждой строки банковской выписки «от
   партнёра»: Admin → Payouts → Collections → «Record collection» (партнёр, сумма, ссылка
   на банковскую транзакцию — `bankTransactionId` уникален, повтор отклонится) → второй
   человек нажимает Confirm. Без confirm сумма не гасит долг партнёра.
   Записать в журнал: сколько строк выписки, сколько записано, сколько подтверждено.
4. **Выплаты партнёрам.** Admin → Settlements: всё в `PAYMENT_PENDING` сверить с
   исходящими платежами банка; совпало — `paid` (второй человек); не совпало через 2
   рабочих дня — `failed` с причиной. Ничего в `REQUIRES_RECONCILIATION` не должно висеть
   больше 2 рабочих дней без propose/confirm.
5. **Idram (когда включат).** Admin → Payments → unresolved attempts: для каждой —
   `RUNBOOK_INCIDENTS_RU.md` §8, два человека с `PSP_RECONCILE`. Сумма
   `psp.payment.captured` за день = сумма зачислений в кабинете Idram за день минус
   комиссии; комиссии записываются как **неизвестные**, пока Idram не даёт их по
   транзакциям — расхождение на сумму комиссий ожидаемо и фиксируется.
6. **Подпись.** Строка журнала заполнена, фамилия, время. Если хоть один шаг дал
   расхождение — статус дня `OPEN` до закрытия по runbook.

## 3. Что делать нельзя

- Править балансы или проводки руками в БД.
- Помечать расчёт `paid`, не увидев платёж в банке.
- Подтверждать collection по словам партнёра без строки выписки.
- Закрывать unresolved-попытку Idram «потому что давно».
- Делать шаги 3–5 одному человеку: запись и подтверждение — разные люди.

## 4. Когда день считается сверенным

- Reconciliation `OK` за день;
- все строки выписки «от партнёров» записаны и подтверждены;
- все исходящие платежи партнёрам отражены как `paid` или `failed`;
- unresolved-попыток PSP нет (или каждая — в процессе propose/confirm с датой);
- журнал подписан.

Пять сверенных рабочих дней подряд — критерий закрытия пункта 27.
