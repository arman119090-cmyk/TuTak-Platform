# Почему не работает карта — и что нужно сделать

Дата: 13 сентября 2026 · ветка `fix/media-and-attempt-races`

## Коротко

Приложение собрано правильно. Карта не рисуется потому, что **MapTiler
отвечает «Invalid key» на каждый запрос тайла**. Ключ, который лежит в
GitHub как секрет `MAP_TILE_API_KEY`, не совпадает с ключом, который знает
MapTiler.

Исправление на вашей стороне — одна минута: заново вставить ключ в секрет.
Мои изменения уже в ветке: сборка больше не сможет молча выпустить APK с
нерабочей картой.

## Как это было доказано

Из этой среды хост `api.maptiler.com` закрыт прокси, поэтому проверка
выполнена с раннера GitHub — тем же способом, что и проверка цепочки
прокси. Диагностический workflow `Check the map tiles` запрашивает один
настоящий тайл над Ереваном и те же данные через маршруты, которые
отвечают словами.

Результат последнего запуска:

| Запрос | Ответ |
|---|---|
| Тайл, ровно как просит приложение (User-Agent + Referer `https://tutak.am`) | **403**, картинка-заглушка |
| Тайл без Referer | **403**, картинка-заглушка |
| Тайл без наших заголовков | **403**, картинка-заглушка |
| TileJSON карты `streets-v2` | **403** — `Invalid key - Get your FREE key at https://cloud.maptiler.com/account/keys/` |
| TileJSON другой карты `basic-v2`, тот же ключ | **403** — `Invalid key` |
| TileJSON `streets-v2` с ключом, у которого убраны пробелы | **403** — `Invalid key` |

Что из этого следует:

- **Это не ограничение по origin.** С нашим Referer и без него ответ
  одинаковый. Если бы ключ был живой, но с белым списком доменов, эти два
  случая различались бы.
- **Это не «карта не входит в тариф».** Вторая карта на том же ключе
  отвергнута так же.
- **Это не лишний пробел или перевод строки.** Вариант с обрезанными
  пробелами отвергнут так же.
- **Это не адрес и не шаблон.** В отчёте печатается собранный URL (ключ
  скрыт), он правильный: `https://api.maptiler.com/maps/streets-v2/256/12/2782/1541.png?key=…`

Дополнительный признак: сохранённый секрет — 20 символов, и в нём есть
символ, который не является латинской буквой или цифрой. Ключи MapTiler
состоят только из букв и цифр. То есть значение в GitHub отличается от
настоящего ключа как минимум одним символом. Ни ключ, ни его часть нигде
не печатаются — проверка сообщает только длину и «буквы/цифры или нет».

Первый запуск этой проверки дал 404 и выглядел как «неправильный
идентификатор карты». Это была моя ошибка в самом workflow: в конструкции
`${TEMPLATE:-https://…/{z}/…}` bash обрывает подстановку на закрывающей
скобке `{z}`, и адрес собирался испорченным. Исправлено; цифры выше
получены уже после исправления.

## Что должны сделать вы (5 минут)

1. Откройте https://cloud.maptiler.com/account/keys/ и скопируйте ключ
   с описанием **TuTak Android Production** — кнопкой копирования, не
   выделением мышью.
2. GitHub → репозиторий → **Settings → Secrets and variables → Actions**
   → секрет **`MAP_TILE_API_KEY`** → **Update**.
3. Вставьте ключ. Убедитесь, что после него нет пробела и перевода строки.
   Сохраните.
4. Проверьте, не нажимая сборку: **Actions → Check the map tiles → Run
   workflow** (ветка `fix/media-and-attempt-races`). Через десять секунд
   в сводке запуска должно быть `HTTP status: 200` и строка
   `Body: (a tile — … bytes)`.
5. Только когда проверка зелёная — **Actions → Build Android APK → Run
   workflow**, профиль `production-apk`, адрес API прежний. Новый APK
   будет с рабочей картой.

Если на шаге 4 снова `Invalid key` — ключ в MapTiler нужно выпустить
заново (Create key) и повторить шаги 1–4. Значит, старый ключ был удалён
или отозван на стороне MapTiler.

Отдельно проверьте в MapTiler, нет ли у ключа ограничений по origin.
Если список «Allowed origins» непустой, в него нужно добавить
`https://tutak.am` — приложение шлёт именно этот Referer. Сейчас это не
причина сбоя, но станет ею, как только ключ заработает.

## Что сделал я

1. **`.github/workflows/map-tile-check.yml`** — диагностика по кнопке.
   Запрашивает настоящий тайл тремя способами и те же данные через
   маршруты, отвечающие текстом. Печатает только коды ответа, тип
   содержимого, слова провайдера и длину ключа — сам ключ и URL с ключом
   не печатаются никогда. Ею же вы проверите исправление на шаге 4.

2. **`.github/workflows/android-apk.yml` — сборка больше не выпустит APK
   с нерабочей картой.** Перед компиляцией делается один запрос тайла тем
   же ключом, который поедет в бинарник. Если провайдер отказывает —
   сборка останавливается и печатает его же формулировку, вместо того
   чтобы двадцать минут собирать установщик, который не нарисует карту.
   Правило берётся по `APP_ENV` профиля, а не по его имени: профиль
   `diagnostic` — это `APP_ENV=preview`, его тоже раздают людям, и правило
   по имени его бы молча пропустило. Сорвавшийся запрос повторяется один
   раз; отказ не повторяется — провайдер уже ответил.

3. **Ключ очищается от пробелов там, где входит в сборку.** Секрет,
   вставленный через браузер, может принести с собой перевод строки;
   провайдер отвергает такой ключ так же, как неправильный, и увидеть это
   можно было только открыв карту на телефоне.

Проверено прогоном шлюза против подставного провайдера во всех четырёх
случаях: отказ, успех, отсутствие ключа в `development`, отсутствие ключа
в `diagnostic`.

## Чего это не меняет

Сообщение «Карта сейчас недоступна. Партнёры ниже — списком.» на вашем
фото — это штатное поведение приложения: оно появляется, когда тайлы не
приходят, и исчезает само, как только они пойдут. Менять в приложении
нечего — там всё правильно, включая строку авторства «© MapTiler ©
OpenStreetMap», которую видно на фото.
