# Карта: провайдер плиток — что выбрано и что нужно от Армана

## Короткий ответ

**Провайдер: MapTiler.** От тебя нужно **одно действие**:

> Зарегистрироваться на maptiler.com, скопировать ключ (Account → API keys) и
> добавить его в GitHub: **Settings → Secrets and variables → Actions**
> — секрет `MAP_TILE_API_KEY`, переменная `MAP_TILE_URL_TEMPLATE` =
> `https://api.maptiler.com/maps/streets-v2/256/{z}/{x}/{y}.png?key={key}`
> и переменная `MAP_TILE_ATTRIBUTION` = `© MapTiler © OpenStreetMap`.

Больше ничего. Ни строчки кода менять не нужно — ни в приложении, ни в
сборке: всё остальное уже сделано.

## Пока ключа нет, установочная сборка не соберётся — и это намеренно

`app.config.js` теперь **отказывается** собирать профили `preview`, `staging` и
`production` без `MAP_TILE_URL_TEMPLATE`. Сборка падает за секунды с текстом,
объясняющим, чего не хватает.

Это добавлено после реального случая: APK #47 собрался, был выложен и описан
как готовый — и только распаковка бинарника показала, что внутри пусто и карта
работает на openstreetmap.org. Такая ошибка ничем себя не выдаёт: приложение
работает ровно до дня, когда OSM его заблокирует, и тогда серый прямоугольник
получают сразу все клиенты.

`development` по-прежнему работает на OSM без всякого ключа — для локальной
разработки это правильно. А `MAP_TILE_ALLOW_FALLBACK=1` позволяет собрать
установочный APK до появления аккаунта: этот флаг нужно набрать руками, в чём и
смысл.

## Почему нельзя оставить как есть

Сейчас плитки берутся с публичных серверов openstreetmap.org. Их политика
использования прямо просит приложения с реальным трафиком уйти к своему
провайдеру: эти серверы работают на пожертвованных мощностях. Это правильный
выбор для разработки и неправильный для приложения, которое раздают клиентам.

Отдельно: та же политика требует, чтобы клиент **представлялся** —
`User-Agent` или `Referer` с именем приложения. Раньше наша карта не
присылала ничего; теперь присылает (см. `tileSource.ts`), и это в любом
случае требуется любым провайдером.

## Почему MapTiler

Рассматривал варианты по одному критерию: подходит ли он **коммерческому**
приложению без переписывания карты.

| Вариант | Итог |
|---|---|
| **MapTiler** | растровые плитки по URL-шаблону, ровно та форма, которую наш код уже умеет; бесплатный тариф покрывает пилот; Армения в покрытии |
| Mapbox | тоже подходит, но тарификация по загрузкам карты сложнее, а SDK нам не нужен |
| Stadia / Stamen | подходит, ключ обязателен, бесплатный тариф жёстче |
| OpenFreeMap | без ключа и без лимитов, но отдаёт **векторные** плитки — наша карта рисует растровые через `<Image>`, это была бы переделка движка |
| Esri / CARTO | формально доступны без ключа, но их условия для коммерческого использования требуют аккаунта — то есть та же регистрация, только без явного тарифа |
| Свой рендерер | машина плюс planet-файл; для пилота это лишняя инфраструктура |

Вывод: любой вариант, пригодный коммерчески, требует аккаунта. Значит,
единственное, что имеет смысл, — сделать подключение **одним действием** и
не требовать от тебя ничего, кроме ключа.

## Что уже сделано с моей стороны

1. **Провайдер вынесен в конфигурацию.** `extra.map` в `app.config.js`:
   шаблон URL, ключ, строка атрибуции. Значение по умолчанию — OSM, то есть
   ничего не ломается, пока ключа нет.
2. **Подстановка ключа в URL** — `{key}` в шаблоне, `{s}` для поддоменов,
   `{z}/{x}/{y}` для координат. Покрыто тестами, включая конфигурацию с
   реальным шаблоном MapTiler.
3. **Атрибуция следует за провайдером** — она у каждого своя, а данные OSM
   в любом случае ODbL и требуют упоминания.
4. **Идентификация клиента** — `User-Agent` из имени и версии приложения
   плюс `Referer`.
5. **Сборка APK умеет переносить эти значения на билдер** (`android-apk.yml`):
   переменные репозитория и секрет попадают в `eas.json` того профиля, каким
   собирается APK. Без этого ключ остался бы на runner'е и не доехал бы до
   машины, которая собирает приложение.

## Как проверить, что заработало

После добавления ключа собери APK обычным способом (workflow «Build Android
APK») и открой карту. Плитки должны прорисовываться, а внизу карты — строка
атрибуции провайдера. Если плитки серые, значит ключ не доехал: в логе
сборки шаг «Put the address where the build can see it» покажет, какие
переменные были подставлены.
