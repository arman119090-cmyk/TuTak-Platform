# Отчёт: обязательная блокировка приложения (код + Face ID / отпечаток)

Дата: 20.09.2026. Ветка: `claude/app-lock`. База: `2eac071` (ветка
`claude/final-integration-20260919`, то есть поверх PR #60, не поверх `main`).

## 1. Задание

Владелец (19–20.09.2026): «Ещё проверь пожалуйста Face ID работает или нет?»,
затем: «я хочу чтобы у нас был фейс айди и … биометрический ключ … когда
человек заходит в application ведёт код или какой-то шрифт и он заходит в
application». Уточнения владельца на вопросы:

- блокировка **обязательна для всех** аккаунтов;
- код из **4 цифр**;
- блокировать **сразу при любом возврате** из фона.

## 2. Что было до задания

Face ID в приложении не работал и не мог работать: в PR #52 был только
черновик биометрического подтверждения через `expo-secure-store`, в
финальной интеграции его не было, `expo-local-authentication` в проект не
входил, экрана блокировки не существовало.

### 3.1. Данные и хранилище

- `apps/mobile/src/data/appLock/pinCode.ts` — код хранится не открытым
  текстом: SHA-256 с солью, 256 раундов (`expo-crypto`), сравнение через XOR
  без раннего выхода. `PIN_LENGTH = 4`.
- `apps/mobile/src/data/stores/appLockStore.ts` — zustand-стор со
  статусами `idle / setup / locked / unlocked`. Ключи SecureStore:
  `tutak.appLock.pin.v1`, `…owner.v1`, `…attempts.v1`. 5 попыток; после
  пятой неверной — сессия сбрасывается, вход заново по SMS. При смене
  аккаунта (`sessionEpoch`) локальный код стирается.
- `apps/mobile/src/data/biometrics/biometricDevice.ts` (+ `.web.ts`) —
  биометрия через `expo-local-authentication` (какой сенсор есть) и
  `expo-secure-store` с `requireAuthentication` (само подтверждение: ключ
  читается только после успешного Face ID / отпечатка). В браузере — заглушка,
  биометрия недоступна.

### 3.2. Экраны

- `PinPad.tsx` — своя клавиатура 3×4, без `TextInput` и системной
  клавиатуры (на Android-устройствах проекта фокус клавиатуры и так капризный).
- `SetPinScreen.tsx` — придумать код, повторить; после сохранения, если
  на телефоне есть Face ID / отпечаток, один диалог с предложением включить.
- `LockScreen.tsx` — экран блокировки: при показе сам вызывает биометрию
  (один раз за показ), иначе код; «Забыли код?» → выход из аккаунта.
- `ChangePinScreen.tsx`, `AppLockSettings.tsx` — в настройках: сменить код,
  включить/выключить биометрию.

### 3.3. Поведение приложения

- `App.tsx`: при уходе в фон (`AppState` → `background`) статус становится
  `locked`; при возврате показывается экран блокировки. Пока приложение
  просто «прикрыто» (шторка, звонок), поверх — заставка, чтобы в
  переключателе задач не был виден баланс.
- `httpClient.ts`: пока приложение заблокировано, ни один запрос к API не
  уходит (кроме `POST /auth/logout`); `queryClient` отменяет запросы при
  блокировке; регистрация push-токена ждёт разблокировки.
- Новые аккаунты: после входа сразу экран «Придумайте код», без него в
  приложение не попасть. Уже вошедшие после обновления — то же при первом
  запуске.

### 3.4. Прочее

- `app.config.js` и `scripts/build-demo-app.sh`: плагины
  `expo-local-authentication` и `expo-secure-store` с текстом разрешения
  Face ID для iOS.
- `packages/i18n`: блок `appLock` — 32 ключа × 3 языка (hy/ru/en).
- `docs/MOBILE_APP_LOCK_RU.md` — описание функции и чек-лист проверки на
  телефоне из 10 шагов.
- `demo/` перегенерирован (проверка паритета в CI).

## 4. Что НЕ сделано и собственные ошибки

- **Сломал e2e-прогон в CI и не заметил до пуша.** Шаг «Drive the built
  mobile app against the stack» собирает приложение для браузера и входит
  демо-пользователем. После блокировки после входа появляется экран
  «Придумайте код», и до `/wallet/me` прогон не доходил. Локально поднял
  Postgres + Redis + API в demo-режиме, воспроизвёл падение на неизменённом
  тесте, затем дописал тесту ввод кода (4 цифры дважды) — проходит.
  Коммит `16c4657`. На `fc904e4` проверка «Build the container images»
  красная именно из-за этого; на `99e1e42` — см. раздел 5.
- **Не проверено на телефоне.** Ни Face ID, ни отпечаток, ни поведение
  при возврате из фона на Samsung/Xiaomi я проверить не могу — только
  через чек-лист в `docs/MOBILE_APP_LOCK_RU.md`.
- **iOS-сборку не делал** — плагин и текст разрешения Face ID добавлены,
  но RC для iOS с этой веткой не собирался.
- Не открывал PR в `main`: ветка стоит поверх PR #60, а PR #60 по решению
  владельца не сливается, пока не закрыты все gates. Открывать PR имеет
  смысл после слияния PR #60 (с rebase).
- Ветка `claude/app-lock` сейчас содержит и следующую задачу (карта,
  коммит `99e1e42`), чтобы владелец получил один APK на обе проверки.
