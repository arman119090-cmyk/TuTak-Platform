# Блокировка приложения: код + Face ID / отпечаток

Решение владельца (20.09.2026): обязательна для всех, код из 4 цифр.
Блокировка — при открытии приложения: каждый холодный старт и возврат
после реального отсутствия (5 минут и дольше в фоне). Первая версия
блокировала при каждом уходе в фон, и на Android это означало код после
каждого системного диалога (разрешение камеры, сам отпечаток) — владелец
попросил убрать это в тот же день.

## Как это выглядит для человека

1. Вход по СМС (или паролю) → экран «Придумайте код» → «Повторите код».
   Пока код не задан, ни один приватный экран не показывается.
2. Если на телефоне есть сильная биометрия (Face ID, Touch ID, отпечаток
   или распознавание лица класса «strong» на Android) — один диалог
   «Использовать Face ID?». «Не сейчас» ничего не ломает: переключатель
   остаётся в Настройки → Безопасность.
3. Каждое открытие приложения (холодный старт, а также возврат после
   5 минут и дольше в фоне): экран «Введите код». Если биометрия
   включена, системный запрос поднимается сам; отмена оставляет
   клавиатуру кода. Короткое отсутствие — системный диалог, быстрый
   переход в другое приложение и обратно — код не спрашивает.
4. Неверный код: «Осталось попыток: N». Пятая ошибка подряд — выход из
   аккаунта, код и биометрическая привязка стираются; дальше только
   вход по СМС и новый код. Это и есть защита четырёх цифр от перебора.
5. «Забыли код? Выйти» — то же самое, по собственному желанию.
6. Настройки → Безопасность: «Изменить код приложения» (сначала текущий
   код, он считается в тот же лимит попыток), переключатель «Вход через
   Face ID / Отпечаток».
7. В переключателе задач (recent apps) вместо баланса показывается
   заставка: приложение прикрывается, как только теряет фокус.

## Что это, а что нет

- Это локальная блокировка уже авторизованного приложения. Серверная
  аутентификация, JWT/refresh и их ротация не меняются.
- Код не хранится: в keystore лежат соль и растянутый SHA-256 (256
  раундов, `apps/mobile/src/data/appLock/pinCode.ts`). Но при 10 000
  вариантах реальная защита — лимит попыток, а не хеш.
- Биометрия — по образцу PR #52: запись в SecureStore с
  `requireAuthentication`, которую ОС инвалидирует при смене набора
  биометрии; приложение не видит лицо или отпечаток. Android требует
  сильную биометрию; обычная разблокировка по фото не предлагается.
- За блокировкой ни один приватный запрос не уходит в сеть (кроме
  logout); refresh токенов не начинается; загрузки отменяются.
- Код и биометрия привязаны к аккаунту на этом телефоне. Выход из
  аккаунта стирает их; другой аккаунт на том же телефоне задаёт свой код.
- Поздний ответ проверки (после сворачивания или выхода) отбрасывается.

## Клавиатура кода — своя

Экран кода не использует `TextInput`: двенадцать `Pressable`-клавиш и
четыре точки. Системная клавиатура на Android — тот самый компонент, у
которого в этом проекте была история с прыгающим фокусом
(`docs/ANDROID_KEYBOARD_*`); экран, который показывается при каждом
запуске, не может на неё полагаться.

## Проверка на телефоне (обязательна до объявления готовности)

1. Установить сборку поверх прежней с уже выполненным входом: при первом
   открытии — «Придумайте код», не главный экран.
2. Ввести разные коды — «Коды не совпадают»; ввести одинаковые — диалог
   про Face ID / отпечаток (если есть) → включить.
3. Свернуть и вернуться: сначала системный запрос биометрии; отменить —
   остаётся клавиатура кода; ввести код — открылось.
4. Полностью закрыть и открыть заново: то же самое.
5. Ввести неверный код 4 раза — счётчик; 5-й раз — выход из аккаунта.
   Войти по СМС — снова «Придумайте код».
6. Настройки → Безопасность → Изменить код: неверный текущий код
   считается в лимит; верный → новый код → «Код изменён».
7. Выключить переключатель биометрии → при следующем открытии только код.
8. Переключатель задач: баланса не видно, только заставка.
9. Армянский и русский языки: заголовки и «Осталось попыток» читаются.
10. iPhone с Face ID проверяется отдельно на физическом устройстве:
    симулятор биометрию только имитирует.
