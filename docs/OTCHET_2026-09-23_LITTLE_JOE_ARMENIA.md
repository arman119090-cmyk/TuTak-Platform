# Отчёт: интернет-магазин Little Joe Armenia (23.09.2026)

## 1. Задание

Спроектировать и реализовать production-grade интернет-магазин Little Joe для
Армении: брендовая витрина, backend, checkout, админка, склад, заказы,
архитектура платежей (наличные при доставке / Idram / Telcell / карта),
мультиязычность **hy (по умолчанию) / ru / it / en**, валюта AMD, SEO,
аналитика, тесты, документация. Не выдумывать ароматы, SKU, EAN, свойства и
историю бренда; сомнительные данные — в очередь проверки с пометкой
«не подтверждено». Не называть магазин «официальным» без подтверждённых прав.

Дополнительное условие владельца: **«сделать так, чтобы вообще не
ассоциировалось» (с существующим проектом TuTak), «не использовать ничего
тут», «только бесплатный Render»**.

Как я это понял и выполнил: магазин — полностью самостоятельный проект в папке
`little-joe-armenia/`, со своим `package.json`, lockfile, `pnpm-workspace.yaml`,
eslint/tsconfig. Он не импортирует и не использует ни одного файла, пакета или
ресурса TuTak (включая Render-базу TuTak). Размещение — только бесплатный план
Render.

## 3. Что сделано

Всё — в `little-joe-armenia/` (≈290 файлов). Стек: Next.js 16.3 (App Router,
proxy.ts), React 19, TypeScript strict (6.0), Tailwind 4, motion, Prisma 7 +
PostgreSQL, Zod 4, React Hook Form, Vitest, Playwright, pnpm.

**Данные и миграции**
- `prisma/schema.prisma`, миграция `prisma/migrations/20260923105152_init` +
  CHECK-ограничения в SQL: остаток ≥ 0, резерв ≥ 0, резерв ≤ остатка, цена > 0,
  диапазоны шкал аромата, рейтинг 1–5, лимит промокода.
- Факты производителя отделены от коммерческих данных Армении; каждый факт
  имеет `ProductFact` (sourceUrl, sourceType, verification, verifiedAt/By).
  EAN, срок действия, размеры, официальное описание показываются на витрине
  **только** со статусом VERIFIED.
- Seed (`prisma/seed.ts`): справочники, 8 шаблонов страниц × 4 языка, демо-
  каталог (9 товаров, `isDemo`, виден только при `DEMO_MODE=true`), очередь
  проверки импорта. Импорт каталога `scripts/import-catalog.ts`: подтверждённый
  факт никогда не перезаписывается — расхождение уходит в ImportReview
  (проверено вручную).

**Витрина** (`src/app/[locale]/…`): главная (hero, «Choose your Joe» с
перекраской по цвету аромата из БД, блок подбора, хиты, семья коллекций, история
бренда только из подтверждённых фактов, отзывы, lifestyle), каталог с поиском и
фильтрами в URL (сайдбар / нижняя шторка), коллекция, семейство аромата,
товар (галерея с зумом, sticky «В корзину» на мобильном, профиль аромата,
факты, отзывы с модерацией, похожие ароматы), подбор аромата (4 вопроса →
топ‑3 с объяснениями из структурированных данных), сравнение до 4, избранное,
корзина (drawer + страница, «отложить», промокод, порог бесплатной доставки),
checkout (гость, телефон AM, адрес по 11 регионам, способы доставки из БД),
страница заказа, песочница оплаты, аккаунт (вход по одноразовому коду,
заказы, адреса, «купить снова»), юридические/справочные страницы с баннером
«требует юридической проверки», локализованный 404.

**Заказы, склад, платежи** (`src/lib/domain`, `src/lib/payments`): машина
статусов из 10 состояний; резервирование атомарным условным UPDATE (гонка за
последнюю единицу даёт ровно одну продажу); журнал движений склада; истечение
резерва; адаптеры CASH_ON_DELIVERY / mock-песочница / Idram (EDP) / заглушки
Telcell и карты; callback-и с проверкой подписи, суммы, идемпотентностью по
(adapter, eventId); оплата после отказа/истечения/отмены обрабатывается без
потери денег.

**Админка** (`src/app/admin`, делал субагент, отчёт
`docs/OTCHET_2026-09-23_LJ_ADMIN.md`): роли OWNER/MANAGER/CONTENT, дашборд,
товары (переводы 4 языков, факты с источниками, аромат, варианты, склад,
медиа с загрузкой файла), коллекции, семейства и теги, заказы (переходы
статусов, заметки, платежи), покупатели, промокоды, отзывы, CMS главной,
настройки (доставка, оплата, контакты, соцсети, SEO, аналитика, юр. данные),
страницы, заявления о бренде, очередь импорта, матрица полноты переводов
HY/RU/IT/EN, журнал аудита, администраторы, `scripts/create-admin.ts`.

**Безопасность**: CSP с nonce, заголовки безопасности, cookies `__Host-`
httpOnly/Secure/SameSite, токены хранятся только хешами, scrypt для паролей,

**SEO/аналитика**: hreflang hy/ru/it/en + x-default, canonical, sitemap только
чистых URL, фильтры — noindex+canonical, JSON-LD Organization/WebSite/
Breadcrumb/Product/Offer, AggregateRating только из одобренных отзывов;
GA4/Meta/TikTok только после согласия, `purchase` — один раз.

**Документация**: `README.md`, `SECURITY.md`, `docs/DESIGN.md`,
`PRODUCT_MODEL.md`, `IMPLEMENTATION_PLAN.md`, `ARCHITECTURE.md`,
`PRODUCT_DATA_SOURCES.md`, `DEPLOYMENT.md`, `EXTERNAL_DEPENDENCIES.md`,
`ASSETS.md`, `.env.example`.

**Развёртывание (бесплатный Render)**: сервис `little-joe-armenia-demo`

Файлы: `Dockerfile.render-demo`, `scripts/render-demo-start.sh`,

## 4. Что НЕ сделано

- **Нет ни одного подтверждённого факта о товарах.** Официальный сайт
  little-joe.com заблокирован прокси окружения; матрица ассортимента Армении
  не передана. Весь каталог — демо: названия из задания и розничных сайтов
  (walmart, popshelf, stonercarcare), цены и остатки условные, семейства
  ароматов выведены из названий, фото — сгенерированные иллюстрации. Всё
  помечено UNVERIFIED и скрыто вне демо-режима.
- **Бесплатную Postgres на Render создать не удалось**: Render ответил
  `cannot have more than one active free tier database` — единственный слот
  занят базой `tutak-staging-db` (истекает 29.09.2026). Её не трогал. Поэтому
  демо работает в одном контейнере со своей Postgres: **данные эфемерные**,
  сбрасываются при каждом засыпании free-инстанса (~15 мин простоя) и
  передеплое. Для реальных заказов это не годится.
- Telcell и банковская карта — только заглушки адаптеров (нет договоров и
  документации); Idram реализован по публично известному протоколу EDP, но не
  сверен с документацией Idram.
- Нет SMS-шлюза: вход по телефону в production недоступен (только email через
  Resend после настройки).
- Юридические тексты — шаблоны с плейсхолдерами, требуют юриста.
- Армянский и итальянский тексты не вычитаны носителями (список сомнительных
  формулировок — в отчётах субагентов и в `docs/EXTERNAL_DEPENDENCIES.md`).
- CI-workflow не добавлен: он лёг бы в общий `.github/` репозитория, что
  противоречит условию «не ассоциировать». Проверки запускаются командами.
- Логотип и фото бренда не использованы (нет прав) — текстовый вордмарк.

**Собственные ошибки по ходу работы**
- `clientIp()` сначала брал *первый* адрес X-Forwarded-For — лимиты можно было
  обойти подменой заголовка (нашёл субагент). Исправлено: берётся последний.
- Оплата, пришедшая после отмены заказа админом, терялась без следа (нашёл
  субагент тестов). Исправлено: платёж фиксируется, заметка «REFUND REQUIRED»,
  аудит; добавлен регрессионный тест.
- В каталоге Suspense-заглушка давала CLS 0.543 — убрал, стало 0.001.
- На 320 px каталог вылезал на 29 px; армянский заголовок рвался посреди слова.
  Исправлено.
- Событие `purchase` помечалось отправленным даже без согласия на аналитику и
  терялось. Переделано на серверный «claim» только при согласии.
- Импорт снимал статус VERIFIED при повторном импорте того же значения.
  Исправлено.
- ESLint 10 оказался несовместим с eslint-plugin-react — откатил на ESLint 9.
- Первые e2e падали из-за неточных селекторов, локали Chromium и моих же
  лимитов частоты (все запросы с 127.0.0.1) — исправлены тесты (сброс
  счётчиков в тестовой БД), лимиты в приложении не ослаблял.
- `pkill -f` в одной из команд убил собственную оболочку — остановил процесс
  по PID.
- Субагенты при ручных проверках временно меняли данные dev-БД; всё откатили,
  в журнале склада остались 3 строки от удалённого тестового заказа.
