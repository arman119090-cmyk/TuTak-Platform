### Найденная поломка №1 — смысловой конфликт слияния

Первый полный прогон дал **1 упавший тест из 1080**:
`test/auth-otp-hardening.int-spec.ts:294`.

```
- Expected  - 0
+ Received  + 1
  Object {
+   "delivered": true,
      "success": true,
  }
```

Это **смысловой конфликт** — тот, который git пропускает, потому что обе
стороны меняли разные файлы. На ветке Viva метод `requestCode` начал
возвращать `{ success, delivered }`; его собственные тесты обновили вместе с
ним, а `auth-otp-hardening.int-spec.ts` живёт в другой линии и продолжал
сверять старую форму через `toEqual` — точное совпадение.

Исправлено утверждением полной новой формы, а не ослаблением до
`toMatchObject`: тест про лимит, который проверяет только `success`, прошёл бы
и на сборке, где первые пять запросов посчитаны, а ни одного СМС не отправлено.

**Это ровно та ошибка, ради которой аудит называл разошедшиеся ветки риском
номер один.** Она сидела в репозитории, и увидеть её можно было только сведя
ветки вместе.

### Найденная поломка №2 — мобильное приложение не запускалось в браузере

CI на `main` показал второе, **и оно было в репозитории до сегодняшнего дня**.

Шаг «Drive the built mobile app against the stack» собирает мобильное
приложение для браузера и водит по нему настоящим Chromium. Он упал:

```
the demo entry never appeared — the app asked the server and either
could not reach it or misread the answer
```

Воспроизвёл локально — приложение не отрисовывалось **вообще**: пустая
страница, ни одного запроса наружу, и ошибка в консоли:

```
Invariant Violation: __fbBatchedBridgeConfig is not set,
cannot invoke native modules
```

Бисекция по 20 мобильным коммитам (экспорт web-бандла и прогон Chromium на
каждом шаге) указала на `a1ffea4` — коммит из расследования клавиатуры. Две
независимые причины, каждой хватало по отдельности:

1. **`focusCommandTrace.ts`** делает
   `require('react-native/Libraries/Components/TextInput/TextInputState')`,
   чтобы отличать «фокус запросили» от «о фокусе сообщили». Проверка
   `isDiagnosticBuild()` внутри не спасает: **Metro решает, что попадёт в
   бандл, читая `require`, а не выполняя его.** В браузере этот путь ведёт в
   настоящий React Native, чей `NativeModules` бросает исключение прямо при
   импорте.
2. **`TextField`** вызывает `findNodeHandle` в эффекте при монтировании.
   `react-native-web` это имя сохраняет и бросает при вызове — а раз это
   происходит в эффекте, падает весь рендер.

**Исправлено так, чтобы поведение на Android не изменилось ни на байт:**

* добавлен `focusCommandTrace.web.ts` — оба экспорта пустые. Платформенный
  файл выигрывает у обычного на web, поэтому спорный путь физически не
  попадает в браузерный бандл, а Android-инструмент работает как работал;
* эффект с `findNodeHandle` закрыт `Platform.OS === 'web'`, а не удалён:
  именно эти строки читают правку `collapsable={false}` обратно из нативного
  дерева на каждом телефоне.

Проверено экспортом и прогоном в Chromium: кнопка демо появляется,
приложение делает ровно один `GET /health`, ошибок на странице нет.

**Важно, кто в этом виноват.** Не слияние. Прогон CI **#527** на
`fix/mobile-api-base-url-railway` — ветке, из которой собран APK №44, —
**был красным на этом же шаге ещё до всего сегодняшнего**. Это не заметили,
потому что не было ствола, относительно которого «красный» что-то значит.
Это и есть цена разошедшихся веток, о которой говорил аудит, — только теперь
в виде конкретного счёта.

## 4. Заодно починен CI

уперевшись в `timeout-minutes: 15` на 15 минутах 13 секундах, когда все наборы

`main` добавляет к тому же шагу наборы OTP и рефералов — она родилась бы
красной. Потолок поднят до 25 минут, с объяснением в самом файле
(`.github/workflows/ci.yml:129-143`). Настоящее решение — разбить набор на
шарды, это отдельный пункт P0-7.

Оговорка честности ради: на `main` этот шаг занял 7:49, то есть вдвое меньше
прежнего потолка. Значит #533 попал в неудачный раннер, а не в системную
границу. Запас всё равно нужен — красная ветка из-за медленной машины стоит
дороже, чем десять лишних минут в настройке.

## 6. Что нужно сделать вам в GitHub — по шагам

Две настройки, обе в веб-интерфейсе. Мне их сделать нельзя: это права над
репозиторием, а не код.

### Шаг 1. Сделать `main` веткой по умолчанию

Сейчас ветка по умолчанию — `claude/tutak-loyalty-mvp-e485jm`, фиче-ветка.

1. Откройте **https://github.com/arman119090-cmyk/TuTak-Platform/settings**
2. Раздел **General** → блок **Default branch**
3. Нажмите значок ⇄ (**Switch to another branch**)
4. Выберите **`main`** → **Update** → подтвердите **I understand, update the default branch**

После этого все новые pull request'ы будут открываться в `main`, а клон
репозитория будет по умолчанию давать `main`.

### Шаг 2. Защитить `main`

1. **Settings** → слева **Branches** (или сразу
   **https://github.com/arman119090-cmyk/TuTak-Platform/settings/branches**)
2. **Add branch ruleset** (новый интерфейс) или **Add classic branch protection rule**

**Если Add branch ruleset:**

| поле | значение |
|---|---|
| Ruleset Name | `main protection` |
| Enforcement status | **Active** |
| Target branches → Add target | **Include default branch** |

Дальше галочки в блоке **Rules**:

| галочка | ставить? | зачем |
|---|---|---|
| **Restrict deletions** | ✅ | нельзя удалить `main` |
| **Block force pushes** | ✅ | нельзя переписать историю |
| **Require a pull request before merging** | ✅ | прямой пуш в `main` запрещён |
| → Required approvals | **0** | пока вы один; поставьте 1, когда появится второй человек |
| → Dismiss stale pull request approvals | ✅ | новый пуш снимает старое одобрение |
| **Require status checks to pass** | ✅ | **самое важное** |
| → Add checks → найти и добавить | **`Lint, test and build`** и **`Build the container images`** | это две задачи из `ci.yml` |
| → Require branches to be up to date before merging | ✅ | ветку нельзя влить, не подтянув `main` |
| Require linear history | ❌ | у нас коммиты слияния, это их запретит |
| Require signed commits | ❌ | пока не нужно, добавит возни |

Нажмите **Create**.

**Важно:** список проверок в «Add checks» появится только после того, как CI
хотя бы раз отработает на `main`. Он уже запущен — если проверок в списке нет,
подождите пару минут и обновите страницу.
