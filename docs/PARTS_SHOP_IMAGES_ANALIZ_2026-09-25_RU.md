## 3. Ответ по существу

### Короткий ответ

Магазин с быстрым поиском и зумом фото — да, это делается без проблем.
**Главная проблема — не техника, а фото**: «скачать из интернета картинку для
каждого кода» — это (а) юридически нельзя, (б) неточно, (в) «сделать
качественнее» с помощью ИИ для запчастей опасно. Правильный путь — брать фото
из лицензированного каталога или у поставщиков.

### Что можно сделать без проблем

| Часть | Как | Проблемы |
|---|---|---|
| Каталог из ваших кодов и названий | Импорт из Excel/CSV в базу | Нет |
| Поиск по коду | Нормализация кода (убрать пробелы, дефисы, точки, регистр): `04465-33471` = `0446533471` = `04465 33471` | Нет |
| Поиск по названию с опечатками | Движок полнотекстового поиска (Meilisearch / Typesense / PostgreSQL trigram) | Нет |
| Поиск на трёх языках (hy/ru/en) | Синонимы: «колодки» / «тормозные колодки» / «brake pads» | Нужен словарь синонимов — его составляем вместе |
| Зум фото | Просмотрщик с приближением пальцами и колесом мыши (PhotoSwipe, OpenSeadragon для очень больших фото) | Нет — **если исходное фото само качественное** |

### В чём проблемы (честно)

**1. Авторское право.** Фото на сайтах производителей, у Exist, Emex,
Autodoc, на Amazon и т.д. кому-то принадлежат. Массово скачать их и поставить
в свой магазин без разрешения — нарушение. Производители дают фото продавцам
легально — через медиакиты или каталоги данных.

**2. Точность: «конкретно его рисунок».** Поиск картинки по коду в интернете
часто возвращает похожую, но другую деталь (другая модификация, левая вместо
правой, фото упаковки, фото чужого бренда-аналога). Для запчастей это
критично: клиент купит не то, будет возврат. Автоматически гарантировать, что
картинка — это ровно этот артикул, по случайному поиску нельзя. Каждое такое
фото пришлось бы проверять человеку.

**3. «Сделать очень качественным».** ИИ-увеличение (upscale) из маленькой
картинки не восстанавливает детали — оно их **придумывает**: форму разъёма,
число контактов, отверстия, резьбу. На витрине запчастей это выглядит
красиво, но может показать то, чего у реальной детали нет. Зум имеет смысл
только на исходно больших фото. Генерировать «рисунки» деталей ИИ тоже
нельзя по той же причине.

**4. Объём.** Если деталей десятки тысяч — ручной подбор фото нереален,
нужен источник данных.

### Как делают профессиональные магазины запчастей

1. **TecDoc (TecAlliance)** — главный мировой каталог автозапчастей:
   более 10 млн артикулов, кросс-номера OE ↔ аналоги, применимость к авто,
   **фото и схемы от самих производителей**. Лицензия платная, цена
   индивидуальная (зависит от объёма и модели бизнеса), продлевается
   ежегодно. Подключается через API — фото приходят официально и
   привязаны к точному артикулу. Для Армении нужно уточнить у TecAlliance или
   их партнёра условия и доступность.
2. **Поставщики / дистрибьюторы**, у которых вы закупаете детали, часто
   отдают прайс вместе с фото (файлом или по API). Это бесплатно и легально —
   стоит спросить первым делом.
3. **Медиакиты брендов** (Bosch, Mann, Febi, Sachs и т.д.) — запрос на фото
   для продавца.
4. **Свои фото** — для ходовых позиций: фотобокс + телефон дают отличное
   качество для зума.
5. Для американского рынка аналог TecDoc — ACES/PIES (SEMA Data, PartsTech) —
   для Армении, скорее всего, менее актуален.

Там, где фото нет, — аккуратная заглушка «фото уточняется» по категории, а не
чужая или придуманная картинка.

### Что Claude может сделать реально

- Спроектировать и написать магазин: каталог, поиск по коду/названию/авто,
  карточка товара с зумом, корзина.
- Написать импорт ваших кодов и названий.
- Подключить TecDoc API или фид поставщика, когда будет доступ, и
  автоматически подтянуть фото по артикулам.
- Написать загрузку и обработку своих фото (нарезка размеров, WebP, CDN).
- Сделать отчёт «у каких артикулов нет фото».

Чего Claude делать не будет: массово скачивать чужие фото с чужих сайтов и
выдавать ИИ-«улучшенные» или сгенерированные картинки за фото конкретной
детали.

## Дополнение (25.09.2026): объём — 1000–2000 позиций

Владелец ответил на вопрос 1: в каталоге около 1000–2000 позиций. Это меняет
вывод.

**Что меняется.** При таком объёме большой платный каталог не обязателен.
Каждое фото можно проверить вручную: при 1–2 мин на позицию это 20–60 часов
работы одного человека (оценка, не замер).

**Рекомендуемый порядок:**
1. Фото от поставщиков — бесплатно, легально, сразу привязаны к коду.
2. Для оставшихся — медиакиты брендов (запрос «фото для продавца»).
3. Для оставшихся — свои фото: фотобокс, съёмка от 3000 px по длинной
   стороне, чтобы зум был резким. Ориентир — 3–5 мин на позицию с
   обработкой, то есть 1–2 недели для 1000 позиций (оценка).
4. TecDoc — только если нужна применимость к авто (подбор по VIN/модели)
   или поставщики фото не дадут.

**Что Claude может сделать под этот объём:**
- админ-страницу «артикул → фото»: загрузка фото, автоматическая
  нарезка размеров и WebP, отметка «проверено», список позиций без фото;
- импорт фото пачкой, если имя файла = код детали (`0446533471.jpg`);
- для позиций без фото — ссылки на поиск по коду, чтобы человек быстро нашёл
  источник и запросил разрешение. Автоматически ставить найденные чужие
  фото на витрину не будет.
