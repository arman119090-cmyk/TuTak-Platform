## Сначала — что значит «готов»

Чтобы слово не означало у нас разное, вот определение, по которому я буду
отчитываться. Готов = выполнены все пять:

1. Нет известных дефектов, из-за которых деньги двигаются неправильно.
2. Данные можно восстановить после аварии.
3. Сбой виден нам раньше, чем клиенту.
4. Приложение, которое раздаём людям, — то самое, что проверял CI, и с рабочей картой.
5. Полный путь клиента пройден руками на живом телефоне.

Сегодня выполнен пункт 1 (после сегодняшних исправлений), частично 4.
Не выполнены 2, 3 и 5.

# ЧАСТЬ 1. Зависит от меня

Всё в этой части я делаю без тебя. Оценки — чистое время работы.

### 1.1 Media: отозванный аватар и частичная запись файлов · ~1 ч
Две проверки: что `REVOKED` аватар не отдаётся по ссылке, и что при сбое одной
из нескольких операций записи в хранилище не остаётся половина файлов.
Осталось от аудита, ещё не проверено мной.

### 1.2 Атомарность счётчиков попыток · ~1 ч
Счётчики попыток ввода кода увеличиваются как «прочитал + 1». Два
одновременных запроса могут прочитать одно и то же число — и получить больше
попыток, чем положено. Нужен атомарный инкремент и тест на параллельный
перебор.

### 1.3 Аудит зависимостей сделать настоящим · ~2 ч
Сейчас шаг в CI помечен `continue-on-error` — он **проглатывает** свои ошибки,
включая критические предупреждения по Next.js. Проверю применимость каждого к
нашему коду по первоисточникам, обновлю версии и сниму заглушку, чтобы шаг
реально блокировал.

### 1.4 Ужесточить защиту карты · ~1 ч
Сегодняшняя защита ловит только пустое значение. Надо также отказывать при:
явно указанном OSM, адресе на `http://`, шаблоне без подстановки ключа,
отсутствии строки копирайта — и запретить аварийный флаг
`MAP_TILE_ALLOW_FALLBACK` для production-профиля.

### 1.5 Идентичность релиза · ~1 ч
Код определяет свой коммит из `GIT_COMMIT_SHA`/`GITHUB_SHA`, но не везде
учитывает переменную Railway, а пустая строка может подавить запасной
вариант — тогда сборка называет не тот коммит. Это ровно тот класс ошибки,
из-за которого вопрос «какая версия на телефоне» уже стоил нам вечеров.

### 1.6 Корректное завершение процесса · ~1 ч
В `main.ts` одновременно есть механизм плавного завершения Nest и свои
обработчики сигналов с немедленным выходом. Второе может обрывать запросы,
которые первое как раз пытается доработать. Проверю и оставлю один путь.

### 1.7 Естественный ключ для сессий роуминга · ~2 ч
Сегодня я закрыл утечку между сетями зарядки проверкой владельца. Правильная
форма — ключ `(партнёр, внешний id сессии)`, чтобы две сети вообще не могли
столкнуться. Это миграция с переносом данных, поэтому отдельным изменением.

### 1.8 Финальный APK · ~30 мин
**Заблокировано пунктом 2.1.** Как только ключ карты появится — запускаю
сборку и проверяю распаковкой, что внутри MapTiler, а не резервные тайлы.
Даю commit, размер, SHA-256 и ссылку.

### 1.9 Живая проверка после каждого слияния · входит в остальное
Отслеживаю деплой до конечного состояния и читаю логи.

**Итого моей работы: примерно 10 часов**, из них 9,5 — не зависят от тебя.

# ЧАСТЬ 2. Зависит от тебя

Здесь я упёрся не в сложность, а в доступ. Для каждого пункта — почему я не

### 2.1 Ключ карты MapTiler · 5 минут · БЛОКИРУЕТ ЗАПУСК
**Почему не могу:** нужен аккаунт у провайдера с подтверждением личности.
Коммерчески пригодного провайдера растровых тайлов без ключа не существует —
я проверил альтернативы.

**Что сделать:** maptiler.com → регистрация (бесплатный тариф, 100 000 тайлов
в месяц) → **Account → API keys** → скопировать ключ → GitHub → **Settings →
Secrets and variables → Actions → вкладка Secrets → New repository secret** →
имя ровно `MAP_TILE_API_KEY` → вставить ключ → **Add secret**.

Адрес тайлов и копирайт подставятся сами. **Ключ вводи прямо в GitHub, мне
присылать не надо.**

### 2.2 Резервные копии базы · 2 минуты · БЛОКИРУЕТ ЗАПУСК
**Почему не могу:** Railway не даёт включать бэкапы через тот интерфейс, к
которому у меня доступ, а для их CLI нужен токен, которого у меня нет. Я
проверил оба пути, включая их собственного агента.

**Что сделать:** Railway → проект TuTak → сервис **Postgres** → вкладка
**Backups** → включить **Daily** и **Weekly** → там же **Enable PITR**.

**Почему это блокирует:** сейчас у боевой базы нет ни одной копии. Первая же
серьёзная ошибка уничтожает данные без возможности вернуть.

### 2.3 Проверить, что копия восстанавливается · 15 минут
**Почему не могу:** восстановление создаёт новый сервис в твоём проекте.

**Что сделать:** после 2.2 дождаться первой копии → **Backups → Restore** на
свежую копию → Railway создаст отдельный сервис, боевой не трогает → убедиться,
что он поднялся → удалить его. Бэкап, который никто не восстанавливал, — это
предположение, а не бэкап.

### 2.4 Railway: не деплоить без CI · 5 минут

# ЧАСТЬ 3. Два решения, которые могу принять только ты

Это не задачи, а выбор. Я не буду делать его за тебя.

### 3.1 Прямой возврат владельцем: оставить или убрать
Ты называл модель C: кассир просит, владелец решает. В коде есть исключение —
владелец может вернуть деньги сам, без второго человека. Аргумент в пользу
исключения записан в самом коде: большинство партнёров — один человек, и
правило, из-за которого он не может вернуть деньги клиенту у стойки, будет
обойдено передачей своего логина кассиру, что хуже.

Сегодня я сделал этот путь честным: он пишет ту же запись, что и обычный
возврат, и отказывает, если по этой покупке уже есть заявка от кассира.
Гонки я исправил независимо от твоего выбора.

**Нужно от тебя:** оставляем исключение или убираем совсем.

### 3.2 Тестовые данные в боевой базе
База работает с 1 сентября, и в ней лежит то, что мы натестировали:
партнёры, покупки, начисления. В нашей же документации по развёртыванию
написано, что первый боевой запуск должен стартовать с чистой базы.

Запуск поверх тестовых данных означает, что настоящие деньги смешаются с
проверочными в отчётах и сверке.

**Нужно от тебя:** чистим базу перед запуском или оставляем. Если чистим — это
делается один раз и до первого клиента; учётную запись администратора и
настройки партнёров придётся завести заново.
