## 1. PR #34 — CI был красный, причина найдена и устранена

Прогон #561 на `7f10db8`: зелёные lint, typecheck, Sentry-parity, unit-тесты,
интеграционные тесты, дрейф миграций, mobile-тесты, сборка трёх образов, e2e,
прогон собранного мобильного приложения против стека, репетиция
бэкапа/восстановления. Красный ровно один шаг — **«The demo app matches the
app it was generated from»**.

Причина: в `apps/mobile` центральное QR-действие получило перехват нажатия
таба (открывает корневой `ScanQr`), а сгенерированная копия в `demo/`
осталась прежней. Гейт сравнивает `demo/` с выводом генератора.

Исправление: запустил штатный `scripts/build-demo-app.sh`, убедился, что весь
диф — это новый блок `listeners` плюс обычные для генератора чистка
комментариев и переформатирование prettier. Руками в `demo/` ничего не правил.

Новый head PR #34: **`3ed59b7`**. Прогон CI перезапущен.

### Почему #32 закрыт, а не влит

После перестановки базы влил `main` в ветку локально. Два конфликта, оба —
случай «`main` строго больше ветки»:

- `auth-otp.service.ts` — в `main` есть и маскирование номера из этой ветки,
  и добавленный позже флаг `delivered`;
- `auth-otp-logging.spec.ts` — в `main` есть тот же describe-блок с
  обновлённым под `delivered` ожиданием плюс второй describe.

Взял версию `main`, и после этого `git diff origin/main HEAD --stat` пустой:
слитый результат побайтово равен `main`. Проверил на слитой версии:
typecheck `@tutak/api` чистый, eslint чистый, unit-тесты **580/580 в 39
наборах** — ровно как на `main`, потому что в ветке нет ничего, чего в `main`
уже нет. Вся работа по Viva (провайдер, `phone-mask.ts` и его спека, тесты
провайдера, три отчёта в `docs/`) в `main` присутствует. Объяснение с
командами оставил комментарием в PR — при необходимости PR переоткрывается.
