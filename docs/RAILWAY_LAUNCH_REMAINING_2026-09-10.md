## 1. Главное, что не работает / не проверено

### 1.1 Реальная доставка СМС — **не подтверждена** ⛔

Это единственный блокирующий пункт и одновременно критерий завершения всей
задачи. Хронология:

| попытка | результат | причина |
|---|---|---|
| напрямую к Viva | `carrier-refused`, `fetch failed` | у Railway нет постоянного исходящего IP, до Viva не достучаться |
| через шлюз, до правки | `carrier-refused`, `HTTP 401 bad_signature` | клиент подписывал `/token/get`, шлюз проверял `/v1/token/get` |
| через шлюз, после правки | **не проверено** | ждём вашего теста |

Исправление задеплоено, но живого теста после него не было. Пока не придёт
реальная СМС — задача не закрыта. HTTP 200 и `success: true` завершением
не считаются (это было оговорено изначально).

### 1.2 Ведущий ноль в OTP — открытый риск

Код уходит строкой (`'012345'`), тестом закреплено, живой доставкой не
подтверждено. Закрывается только настоящей СМС с кодом, начинающимся с
нуля. Пока — риск примерно одного входа из десяти.

### 1.3 Per-IP лимиты отключены — предупреждение в логах при каждом старте

```
Request rate limiting is STOOD DOWN: req.ip is the load balancer, so every
caller shares one bucket and any single client could lock the rest out.
```

`CLIENT_IP_STRATEGY` и `CLIENT_IP_TRUSTED_HOPS` не заданы (по плану — их
нельзя было задавать вслепую, нужно измерить число хопов на живом сервисе).
Сейчас работают: глобальный бюджет СМС и блокировка по аккаунту. Не
работают: лимиты на одного звонящего. Для теста это приемлемо, **для
запуска с пользователями — нет**.
