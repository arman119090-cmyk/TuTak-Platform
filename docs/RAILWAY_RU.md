# Развернуть TuTak на Railway с телефона

Второй способ развернуть демонстрацию, рядом с `render.yaml`. Тот же образ,
те же переменные — разница только в хостинге.

Здесь описан **API**. Панель администратора и кабинет партнёра для показа
приложения на телефоне не нужны: мобильное приложение разговаривает только с
API. Их можно добавить теми же тремя шагами позже.

## Честный статус

Этот конфиг **не был развёрнут мной** — из моей среды исходящие соединения к
Railway блокируются политикой сети. Он написан по опубликованной схеме Railway
и по тому, что образу действительно нужно, а сам образ собирается и
запускается ежедневно в CI. Если Railway на чём-то споткнётся — переменные
окружения перечислены ниже полностью, и они одни и те же для любого хостинга,
который умеет запустить контейнер, Postgres и Redis.

## Что получится

Один сервис API в демо-режиме, с базой и Redis рядом. Платежи идут на
песочном эквайере: ни один банк не задействован, ни одна карта не
списывается. API сообщает об этом на `/health` и в собственном логе при
старте.

**Никому нельзя показывать это как обработку настоящих денег.**

## Шаги

Всё делается в браузере, телефон подходит.

### 1. Создать проект из репозитория

railway.com → **New Project** → **Deploy from GitHub repo** → выбрать этот
репозиторий, ветку `claude/tutak-loyalty-mvp-e485jm`.

Railway найдёт `railway.json` в корне и соберёт образ по
`apps/api/Dockerfile`. Первая сборка идёт около пяти минут.

### 2. Добавить базу и Redis

В том же проекте: **New** → **Database** → **Add PostgreSQL**. Потом ещё раз
**New** → **Database** → **Add Redis**.

Railway сам подставит `DATABASE_URL` и `REDIS_URL` в сервис API — вписывать
их руками не нужно.

### 3. Вписать переменные

Сервис API → вкладка **Variables** → **Raw Editor** → вставить целиком:

```
NODE_ENV=production
DEMO_MODE=true
DEMO_SEED=true
SWEEPS_ENABLED=true
QUEUE_PREFIX=tutak-demo
JWT_ACCESS_SECRET=<длинная случайная строка>
JWT_REFRESH_SECRET=<другая длинная случайная строка>
SEED_ADMIN_PASSWORD=<не короче 12 символов>
DEMO_PASSWORD=<не короче 12 символов>
CORS_ORIGINS=https://example.invalid
```

Про каждую, коротко:

| Переменная | Зачем |
| --- | --- |
| `DEMO_MODE` | Разрешает песочный эквайер и заглушку SMS. Без неё процесс с `NODE_ENV=production` откажется стартовать на поддельном эквайере — это защита, а не помеха |
| `DEMO_SEED` | Создаёт демо-данные при старте: партнёров, клиентов, покупки, бонусы, зарядные сессии. Без неё приложение войдёт, но все экраны будут пустыми |
| `DEMO_PASSWORD` | Общий пароль всех демо-аккаунтов. Сидер отказывается работать без него и отказывается принимать короче 12 символов. **Он же нужен кнопке «Войти в демо» в приложении** |
| `JWT_*_SECRET` | Подписывают токены сессий. Смена разлогинивает всех — поэтому они не выводятся ни из чего другого |
| `CORS_ORIGINS` | Список источников для веб-панелей. Для показа мобильного приложения панели не нужны, но переменная обязательна: без неё API в production не стартует, а не начинает принимать запросы отовсюду. Оставьте заглушку и замените, когда появятся панели |

Секреты придумайте любые длинные — они нигде не хранятся в репозитории.
`openssl rand -base64 32` в любом онлайн-генераторе или просто длинная
случайная фраза подойдут.

### 4. Открыть адрес наружу

Сервис API → **Settings** → **Networking** → **Generate Domain**.

Railway выдаст адрес вида `https://tutak-api-production.up.railway.app`.

### 5. Проверить

Откройте в браузере телефона:

```
<ваш-адрес>/v1/health
```

Должно ответить:

```json
{ "status": "ok", "demoMode": true }
```

Если `demoMode` — `false`, переменные не подхватились: вернитесь к шагу 3 и
передеплойте.

Если страница не открывается вовсе — посмотрите вкладку **Deployments**, там
лог. Чаще всего это одна из обязательных переменных, и в логе будет написано
какая: API специально отказывается стартовать с неполной конфигурацией, а не
запускается наполовину.

### 6. Собрать APK на этот адрес

GitHub → **Actions** → **Build Android APK** → **Run workflow**.

В поле **API URL** впишите адрес **с `/v1` на конце**:

```
https://ваш-адрес.up.railway.app/v1
```

Через ~15 минут APK будет внизу страницы запуска, в разделе **Artifacts**.

## Вход без регистрации

На экране входа появится кнопка **«Войти в демо»**. Она есть только тогда,
когда сервер сам сообщил `demoMode: true` — приложение это не решает за него.
Тот же APK, направленный на настоящий API, никакой кнопки не покажет.

Кнопка входит демо-клиентом `+374 77 100 001` — у него есть кошелёк с
бонусами, история покупок, приглашённый друг и зарядная сессия, так что
экраны не пустые.

Если предпочитаете войти вручную, эти же данные работают в обычной форме:
номер `+374 77 100 001` и пароль, который вы задали в `DEMO_PASSWORD`.

## Стоимость

У Railway нет бессрочного бесплатного тарифа — есть пробный кредит. Демо
такого размера расходует его медленно, но следить стоит: на вкладке **Usage**
видно остаток. Если кредит кончится, сервис остановится, а не выставит счёт
молча.

Альтернатива без карты — `render.yaml` в корне репозитория: там всё на
бесплатном тарифе, ценой того, что сервис засыпает через 15 минут простоя и
просыпается 30–50 секунд.
