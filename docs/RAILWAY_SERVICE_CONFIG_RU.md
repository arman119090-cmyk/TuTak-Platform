# Почему в репозитории больше нет `railway.json`

Railway читает `railway.json` из корня репозитория **для каждого сервиса,
который собирается из этого репозитория**, и этот файл перекрывает настройки,
заданные в самом сервисе.

В проекте TuTak из одного репозитория собираются три сервиса — `tutak-api`,
`tutak-admin`, `tutak-partner`. Корневой `railway.json` указывал
`apps/api/Dockerfile`, поэтому админка и партнёрский кабинет собирали образ
API и падали при старте:

```
Error code: P1012
error: Environment variable not found: DATABASE_URL.
  -->  prisma/schema.prisma:16
```

Prisma в контейнере админки — это и есть признак: запускался не тот образ.
Настройка `dockerfilePath` на уровне сервиса при этом была задана правильно и
просто не действовала.

Файлы `railway.admin.json` и `railway.partner.json` Railway не читал никогда:
альтернативный путь к конфигу задаётся в настройках сервиса, а этот механизм
объявлен устаревшим.

## Как настроено сейчас

Конфигурация сборки и проверки живёт в настройках каждого сервиса Railway:

| сервис | Dockerfile | healthcheck | порт |
|---|---|---|---|
| `tutak-api` | `apps/api/Dockerfile` | `/health` | 4000 |
| `tutak-admin` | `apps/admin/Dockerfile` | `/login` | 3000 |
| `tutak-partner` | `apps/partner/Dockerfile` | `/login` | 3001 |

Политика перезапуска у всех трёх — `ON_FAILURE`, не более 3 попыток,
таймаут проверки 120 секунд.

## Если понадобится вернуть конфиг в код

Возвращать корневой `railway.json` нельзя, пока из репозитория собирается
больше одного сервиса, — он снова перекроет настройки всех трёх. Актуальный
способ — `.railway/railway.ts` с раздельными настройками по сервисам.
