## Важно: патч в нынешнем виде уронит API на старте

Проверено по составу самого патча, а не по предположению. Из SMS-переменных в
нём есть только три:

```
SMS_AUTH_SCHEME
SMS_ENCODING
SMS_SENDER
```

**Нет ни одной из решающих:** `SMS_DRIVER`, `SMS_ENDPOINT`,
`VIVA_API_BASE_URL`, `VIVA_CLIENT_ID`, `VIVA_CLIENT_SECRET`, `VIVA_USERNAME`,
`VIVA_PASSWORD`, `VIVA_OTP_TEMPLATE_NAME`, `SMS_VIVA_NUMBER_FORMAT`.

`DEMO_MODE` в патче тоже нет, а `APP_ENV` есть. При `APP_ENV=production` и
незаданном `DEMO_MODE` `selectSmsTransport` доходит до ветки

> `SMS_ENDPOINT must be configured in production — verification and password
> reset codes cannot be delivered without a carrier.`

и **бросает исключение на старте**. Приложение не поднимется. Это ровно тот
блокер, который отчёт о готовности предсказывал 3 сентября; теперь он
подтверждён составом реального патча.

Хорошая новость: чинится это тем, что уже готово — набором переменных Viva из
этапа B, значения для которых у вас есть с 8 сентября.

## Варианты — решение за вами

### Вариант 1. Тестовое окружение остаётся на Render (быстрее всего)

Ничего нового не нужно. Разворачиваем этап A — коммит `d23946e`, ветка
`deploy/staging-api-d23946e` — на `tutak-staging-api`, как и планировали. APK42
уже смотрит туда, пересобирать нечего.

**Рекомендую этот вариант**, пока Railway production не поднят: он ничего не
блокирует и даёт наблюдаемость там, где вы реально тестируете.

### Вариант 2. Завести на Railway отдельное окружение `staging`

Railway это умеет: окружение можно создать рядом с `production`, со своими
переменными и своим доменом. Тогда:

1. создать окружение `staging`;
2. развернуть в нём этап A;
3. завести переменные Viva (этап B) — **в staging, не в production**;
4. пересобрать диагностический APK на новый адрес.

Дольше, но это правильная конструкция: production перестаёт быть единственным
местом, где вообще что-то можно проверить.

### Вариант 3. Поднять production на Railway

Отдельная задача, не тестовая. Перед ней нужно дозаполнить патч — минимум
переменными SMS, иначе первый же старт упадёт (см. выше). Тестировать на нём
всё равно нельзя.
