## Домен: адрес Railway, без покупки своего

Принято: `*.up.railway.app`, HTTPS. Свой домен не покупаем.

HTTPS на таком адресе Railway выдаёт и продлевает сама — сертификат
оформляется при генерации адреса, отдельной настройки не требует. Проверим это
не на слово: после генерации открываем `https://<адрес>/health` и смотрим, что
соединение защищено и ответ приходит.

Адрес попадает в три места, и все три — ссылками на `RAILWAY_PUBLIC_DOMAIN`,
а не переписанной строкой:

| переменная | значение |
| --- | --- |
| `MEDIA_PUBLIC_BASE_URL` | `https://${{RAILWAY_PUBLIC_DOMAIN}}` |
| `CORS_ORIGINS` | `https://${{RAILWAY_PUBLIC_DOMAIN}}` |
| адрес API в новом APK | тот же адрес + `/v1`, вписывается при сборке |

Ссылка, а не копия: при смене адреса Railway обновит её сама, а скопированная
строка молча устареет.

**Порядок жёсткий:** сначала генерируем адрес, потом проверяем, что
`RAILWAY_PUBLIC_DOMAIN` непустой, и только потом задаём эти две переменные.
Причина — в поправке №1: при пустом домене значение становится `https://`,
`new URL('https://')` бросает исключение внутри `isLoopbackOrigin`, `catch`
возвращает `false`, и защита пропускает битый адрес. Приложение поднимется
молча неправильным.

### Ещё одно, найденное при этой проверке: порт

`Dockerfile` объявляет `EXPOSE 4000`, а приложение слушает
`process.env.PORT ?? 4000`. Railway подставляет свой `PORT` — и если он не
4000, маршрутизация пойдёт на 4000, а приложение будет слушать другой порт.
Внешне это выглядит как «healthcheck не проходит», без объяснения.

**Поэтому в набор переменных добавляется `PORT=4000`.** Тогда объявленный порт,
слушающий порт и порт маршрутизации совпадают. Одна строка, снимает целый класс
отказа первого деплоя.

## ШАГ 1 — единственное, что нужно сделать сейчас

### Где найти патч

1. Открыть Railway → проект **`TuTak`**.
2. Убедиться, что выбрано окружение **`production`** (переключатель окружений
   вверху; других окружений в проекте нет).
3. На канве проекта сервисы `TuTak-Platform`, `tutak-admin` и `tutak-partner`
   отрисованы **пунктиром** — это заготовки, которых ещё нет. Значит патч на
   месте.
4. Сверху появится панель ожидающих изменений — кнопка с числом изменений
   (**70**) и рядом кнопки применить / отменить. В разных версиях интерфейса
   она называется по-разному: *Staged changes*, *Pending changes* или
   *N changes*.

### Что нажать

**Discard** (отменить). **Не Deploy и не Apply.**

Если интерфейс попросит подтверждение — подтвердить отмену изменений.

### Как убедиться, что отменён именно тот патч

Перед нажатием разверните список изменений. В нём должны быть строки об
удалении переменных у **живых** баз — это и есть та причина, по которой патч
нельзя применять:

```
Postgres → DATABASE_URL, PGDATA, PGDATABASE, PGHOST, PGPASSWORD,
           PGPORT, PGUSER, POSTGRES_DB, POSTGRES_PASSWORD,
           POSTGRES_USER, SSL_CERT_DAYS …           removed
Redis    → REDISHOST, REDISPASSWORD, REDISPORT,
           REDISUSER, REDIS_PASSWORD, REDIS_URL     removed
```

Плюс создание трёх сервисов и одного бакета. Всего 70 изменений, дата — 3
сентября. Если видите это — патч тот самый.

### Что произойдёт и чего не произойдёт

**Произойдёт:** исчезнут три пунктирные заготовки сервисов и заготовка бакета.

**Не произойдёт:** Postgres и Redis остаются как есть, со всеми своими
переменными и томами. **Данные не удаляются.** Ни один работающий сервис не
перезапускается.

Отмена патча ничего не разворачивает и не тратит денег.

Прошу разрешить **создание и запуск одного сервиса API**. Больше ничего.

| | |
| --- | --- |
| **Что создаётся** | один сервис `tutak-api` в существующем окружении `production` проекта `TuTak` |
| **Из чего** | репозиторий `arman119090-cmyk/TuTak-Platform`, ветка `deploy/railway-api-df1fd99` |
| **Коммит** | `df1fd996eaf089e91f10d5f6e3698d280a6f5794` |
| **Плюс к сервису** | сгенерированный адрес `*.up.railway.app` — бесплатный |
| **Что НЕ создаётся** | ни баз, ни Redis, ни томов, ни бакета, ни admin, ни partner |
| **Оценка расходов** | **≈ $7 в месяц** при круглосуточной работе: 0.5 ГБ RAM × $10 + 0.1 vCPU × $20 + трафик до $0.05. Допущения и что их сдвинет — в разделе 4 основного запроса. Postgres и Redis уже работают и уже стоят денег с 1 сентября; в эту сумму не входят |

Порядок остаётся прежним и все прежние уточнения в силе:

1. **До создания** — вы проверяете, что база чистая, запросом к
   `_prisma_migrations` (поправка №3). Есть строки — останавливаемся, я сверяю
   список миграций до того, как `migrate deploy` их применит.
2. Создаю сервис → **сразу генерирую адрес** → проверяю `https://…/health` и
   что `RAILWAY_PUBLIC_DOMAIN` непустой.
3. Задаю несекретные переменные, включая `PORT=4000`. **Viva пока не задаю.**
4. Вы вводите `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`,
   `SEED_ADMIN_PASSWORD` — в панели, не в чат.
5. Первый деплой. Проверки: `/health` с `demoMode: true`, в журнале
   `SMS transport: unavailable`, `POST /v1/auth/demo-session` → 404, миграции
   применились.
6. **Отмена первого запуска — остановка сервиса**, а не Rollback: предыдущего
   деплоя ещё нет. Postgres, Redis и данные при этом не трогаются.
7. Дальше — Viva: сначала связь и авторизация, потом согласованная отправка на
   ваш номер (поправка №4). Шлюз Contabo остаётся запасным путём.
8. Новый APK — из `claude/android-keyboard-diagnostics-20260908` (`1993e1b`,
   410 тестов), а не из старого `apps/mobile` в ветке API. До этого APK42
   остаётся на Render.
