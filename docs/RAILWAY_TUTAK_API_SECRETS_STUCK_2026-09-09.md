# Секреты tutak-api не применились — найдена причина, 09.09.2026

## Итог одной строкой

Три секрета (`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `SEED_ADMIN_PASSWORD`),
добавленные вами через панель Railway, **не стали живыми** — они повисли в
том же незавершённом staged-патче, что и старая проблема с переменными
Postgres/Redis. Первый деплой `tutak-api` из-за этого упал (`CRASHED`).
Я ничего не удалял, не деплоил и не генерировал секреты за вас.

Вывод: `DATABASE_URL`, `REDIS_URL` и остальные 13 несекретных переменных,

через панель, — нет.

## Почему секреты не применились

Проверка `get-staged-changes` показывает: `JWT_ACCESS_SECRET`,
`JWT_REFRESH_SECRET`, `SEED_ADMIN_PASSWORD` числятся как **`added`** (то есть
по-настоящему ждут применения) в **том же самом** незакрытом патче
`e0b2070b-341d-4fdb-9590-a3d4e55c78ee`, который с 1 сентября содержит
удаление переменных Postgres/Redis. Число изменений в патче выросло с 37 до
**40** ровно на эти три пункта.

По документации Railway (docs.railway.com/deployments/staged-changes) — в
проекте в любой момент времени существует **один** общий набор отложенных
изменений на окружение. Любое новое изменение через панель (включая ваши
секреты) добавляется в этот же набор, а не применяется отдельно. Раз старый
набор с 1 сентября так и не был закрыт (ни задеплоен, ни по-настоящему
отменён), ваши секреты присоединились к нему же.

`list-variables` подтверждает: среди переменных `tutak-api` секретов нет —
они не в живом конфиге.

## Что нужно сделать (руками, в панели Railway)

Документация Railway прямо описывает нужный инструмент: в баннере
"N staged changes" есть кнопка **"Details"**, где у каждой строки изменения
справа есть крестик **"x"** — им можно отменить (discard) ровно одну строку,
не трогая остальные.

1. Откройте проект `TuTak` → окружение `production` → баннер staged changes →
   **Details**.
2. Крестиком уберите все строки **кроме** трёх новых: `JWT_ACCESS_SECRET`,
   `JWT_REFRESH_SECRET`, `SEED_ADMIN_PASSWORD` на `tutak-api`. Это все
   переменные Postgres (`DATABASE_URL`, `PGPASSWORD` и т.д.), все переменные
   Redis (`REDIS_URL` и т.д.), алерты по томам, и повторно всплывающие 13
   переменных `tutak-api`, которые уже живые (их можно смело убирать из
   патча — на самом деле они уже работают, что подтверждено логами выше).
3. Когда в списке останутся только три новых секрета — нажмите **Deploy**.
   Это должен быть чисто аддитивный шаг: три новые переменные, без удаления
   чего-либо.
4. Напишите мне — я проверю журнал нового деплоя.

Если крестики неудобны или их окажется много — альтернатива: установить
Railway CLI и выполнить `railway variables --set JWT_ACCESS_SECRET=... --set
JWT_REFRESH_SECRET=... --set SEED_ADMIN_PASSWORD=... --service tutak-api
--environment production`. CLI, по моим наблюдениям, применяет переменные
напрямую (так же, как мои вызовы API), минуя эту зависшую очередь.
