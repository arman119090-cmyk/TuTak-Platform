## Дальше — шаг 6: реальная СМС на согласованный номер

Важно: успешный тест Viva 8 сентября шёл с другой машины напрямую — то, что
транспорт инициализировался на Railway, **не доказывает**, что Viva примет
исходящий адрес Railway. Это первая живая проверка с этого хоста.

Я не могу сам отправить тестовый запрос — исходящий доступ из этой рабочей
среды к публичному домену `tutak-api-production.up.railway.app`
заблокирован сетевым прокси. Нужно, чтобы вы (или мобильное приложение)
сделали **один** запрос кода на согласованный номер — регистрацию или вход
через мобильное приложение, указывающее на этот адрес, либо вручную через
`POST /v1/auth/register` (или `/v1/auth/login`) с этим номером.

После запроса пришлите, что произошло (пришла СМС или нет), и я прочитаю
журнал по таблице из общего плана:

| в журнале | что значит | что дальше |
|---|---|---|
| `carrier-refused` + сеть/таймаут | до Viva не достучались | адрес Railway не в списке разрешённых → шлюз |
| `carrier-refused` + отказ авторизации | связь есть, ключи не приняты | сверить учётные данные |
| `carrier-refused` + `RC != 0` | отказ Viva по существу | шаблон, отправитель, формат номера |
| `code-handed-to-carrier`, СМС нет | приняли, не доставили | вопрос к Viva с `transact_unique_id` |
| `code-handed-to-carrier`, СМС пришла | **работает** | вводим код |

Номер телефона, сам код и журнал с персональными данными в чат и в
документы не выводим — только категорию исхода.
