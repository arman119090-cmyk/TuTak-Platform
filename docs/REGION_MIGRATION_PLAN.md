# План миграции региона Railway (sfo → Европа) — черновик для решения владельца

Дата: 26.09.2026. Статус: **OWNER DECISION, не выполняется агентом**
(смена региона — в списке STOP).

## Факты

- Все сервисы production в регионе `sfo` (US West): `describe-environment`,
  `multiRegionConfig: { sfo: { numReplicas: 1 } }` у `tutak-api`. Бакеты —
  `sjc`. Пользователи и партнёры — Армения.
- Латентность Ереван ↔ Калифорния по сети ≈ 180–250 мс RTT (оценка по
  географии; **из этой среды не измерена** — исходящие соединения к production
  закрыты прокси). Подтверждение покупки — самая тяжёлая транзакция
  (несколько round-trip внутри одного запроса, но все они API ↔ Postgres в
  одном регионе, так что страдает только внешняя часть: телефон ↔ API).
- Railway предлагает регион EU (Амстердам, `europe-west4`): ≈ 60–80 мс до Еревана.
- Кастомных доменов нет; APK зашит на `tutak-api-production.up.railway.app`.

## Что означает миграция

Railway меняет регион **на уровне сервиса** (Settings → Region) с пересозданием
контейнера; **том Postgres регион не меняет** — данные нужно переносить:
дамп/восстановление (`scripts/backup.sh` → новый Postgres в EU →
`scripts/restore.sh`) или базовый бэкап + WAL (`pitr-*`). Это даунтайм записи
на время переноса (минуты при текущем объёме 5 GB тома, реально занято меньше).

## Порядок (если владелец решит)

1. **Сначала домен.** Купить домен, привязать к `tutak-api` (Railway → Custom
   domain), выпустить APK на домен. Иначе любая пересборка адреса ломает
   установленные приложения.
2. Объявить окно; `EMERGENCY_FREEZE=true` на `tutak-api` (503 на записи,
   чтение работает) — с `adb30a8f` это одна переменная.
3. Новый сервис Postgres в EU; `backup.sh` со старого → `restore.sh --into` в
   новый; проверить `restore.sh --verify` (леджер сходится).
4. `tutak-api`, `tutak-admin`, `tutak-partner`: Settings → Region → EU;
   переключить `DATABASE_URL` на новый Postgres (reference variable);
   Redis — пересоздать в EU (сессии/очереди переживают, refresh-токены в
   Postgres).
5. `/health/ready` = 200; `alert:verify`; smoke (`scripts/smoke-test.sh`
   против нового адреса); снять freeze.
6. Старый Postgres — держать read-only 7 дней, потом удалить (решение владельца).
7. WAL-архив (`WAL_ARCHIVE_*`) перенастроить на новый бакет в EU; повторить
   учение восстановления.

## Когда НЕ делать

- До переноса проекта Railway на аккаунт владельца (`INFRASTRUCTURE_OWNERSHIP.md` §3):
  два больших изменения инфраструктуры одновременно — плохая идея.
- До запуска пилота, если пилот на 5–10 партнёрах: 200 мс на подтверждение
  покупки терпимо; мигрировать лучше между пилотом и публичным запуском.
