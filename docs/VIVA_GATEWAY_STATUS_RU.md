## 5. Архитектура

```
TuTak API (Railway)            Contabo VPS                Viva
  VivaSmsProvider              nginx :443 (TLS)
    │ HTTPS + HMAC               │ 127.0.0.1:8443
    │ Timestamp/Nonce/Signature ─► viva-gateway.mjs
    │                             │  · только 4 пути
    │                             │  · upstream — константа
    │                             │  · fail-closed по туннелю
    │                             ▼
    │                         strongSwan ══ IPsec/IKEv2 ══► businesshubapi.viva.am
```

Railway остаётся основной инфраструктурой: API, БД, Redis, Admin, Partner,
mobile — ничего не переносится. VPS делает одно: терминирует туннель и
пересылает четыре запроса.

**Почему HMAC, а не IP allowlist или bearer.** У Railway Hobby нет постоянного
исходящего IP — allowlist пришлось бы делать настолько широким, что он ничего
не значит. Bearer доказывает только владение, и навсегда: всё, что его хоть раз
увидит, сможет слать SMS с нашего счёта Viva. HMAC подписывает timestamp, nonce,
метод, путь и хеш тела: секрет не передаётся, перехваченный запрос не
повторить, подпись от `show/progress` не переставить на `send/batch`. mTLS
сильнее и назван в runbook как следующий шаг — сейчас не выбран, потому что
клиентский ключ через переменные Railway это больше движущихся частей, чем
оправдано, на пути логина.

## 6. Какие ENV нужны TuTak

Новая — одна:

```
SMS_VIVA_GATEWAY_SECRET=<openssl rand -hex 32>
```

И `SMS_ENDPOINT` меняется с адреса Viva на адрес gateway:

```
SMS_ENDPOINT=https://viva-gw.tutak.am/v1
```

Тот же секрет кладётся на VPS в `/etc/viva-gateway/gateway.env`. Staging и
production — **разные секреты и разные FQDN**. Остальные `SMS_VIVA_*` не
меняются.
