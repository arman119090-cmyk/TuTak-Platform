## Короткий ответ

Файл `.apk` собирается либо на серверах Expo (EAS), либо локально через
Android SDK. **Оба пути из моей среды закрыты сетевой политикой**, а третий
вариант — выполнить сборку на вашем сервере Contabo — закрыт тем, что порт
SSH наружу из моей среды тоже блокирован. Это ограничения инфраструктуры,
их нельзя снять разрешением в переписке.

Код при этом готов полностью, и я это проверил — см. раздел 6.

## 1. Что нужно, чтобы получился .apk

Приложение написано на Expo SDK 57 / React Native. Чтобы из исходников
получился устанавливаемый файл, нужно:

1. скомпилировать нативную часть Android (Gradle + Android SDK);
2. собрать JS-бандл (это единственная часть, которую я могу сделать);
3. подписать результат ключом (keystore) — иначе Android откажется его
   ставить, а с чужим ключом он не встанет поверх уже установленного.

Пункты 1 и 3 — то, чего у меня нет.

## 2. Путь А — EAS Build (серверы Expo). Закрыт

Штатный путь: `eas build` отправляет исходники на серверы Expo, там идёт
компиляция и подпись хранимым ключом, на выходе — ссылка на APK.

Проверка доступа из моей среды:

```
$ curl https://api.expo.dev
curl: (56) CONNECT tunnel failed, response 403

$ curl https://expo.dev
curl: (56) CONNECT tunnel failed, response 403
```

Статус сетевого прокси среды подтверждает, что это именно запрет политики:

```json
{
  "kind": "connect_rejected",
  "detail": "gateway answered 403 to CONNECT (policy denial or upstream failure)",
  "host": "cdp.expo.dev:443"
}
```

В белом списке этой среды есть `registry.npmjs.org`, GitHub, Railway —
поэтому туда я хожу свободно и оттуда же деплою API. Домены Expo в список не
входят. **Токен Expo здесь не поможет**: запрос отклоняется до всякой
авторизации, на уровне установления соединения.

## 3. Путь Б — локальная сборка APK в моей среде. Закрыт

Теоретически APK можно собрать без Expo — через `expo prebuild` и Gradle.
Проверил, чего для этого не хватает:

| компонент | состояние |
|---|---|
| Java (JDK 21) | ✅ есть |
| Gradle (`services.gradle.org`) | ✅ доступен (200) |
| `maven.google.com` | ✅ доступен (301) |
| **Android SDK** | ❌ не установлен, `ANDROID_HOME` не задан |
| **`dl.google.com`** — откуда качается Android SDK | ❌ недоступен (соединение не устанавливается) |

Без Android SDK нативную часть не скомпилировать, а скачать его неоткуда —
единственный источник заблокирован.

Даже если бы SDK был, оставалась бы вторая проблема: **ключ подписи**. Он
хранится в вашем аккаунте Expo, у меня его нет. APK, подписанный любым
другим ключом, **не установится поверх** приложения, которое уже стоит у
людей — им пришлось бы сначала удалять приложение со всеми данными.

## 5. Почему казалось, что я уже собирал APK

В отчёте прошлой сборки (`docs/ANDROID_APK_2026-09-02.md`) написано прямо:

> «**Устройства у меня нет** — это ограничение названо честно в разделе D.»
>
> «**Сборка Android-бандла целиком** — `expo export --platform android`,
> 5 МБ Hermes-байткода, код возврата 0.»

`expo export` — это сборка **JS-бандла**, локальная операция без Expo и без
Android SDK. Она доказывает, что код собирается, но файла `.apk` не даёт и
на телефон не ставится.

То есть APK ни в одной сессии я не собирал. Код готовил я, а саму сборку
через EAS запускали вы — отсюда и ощущение, что «вчера собирал».

## 7. Что осталось сделать вам — одна команда

На любой машине с обычным интернетом (компьютер или ваш сервер Contabo):

```
npx eas-cli@latest login
cd ~ && git clone --depth 1 -b fix/mobile-api-base-url-railway \
  https://github.com/arman119090-cmyk/TuTak-Platform.git
cd TuTak-Platform/apps/mobile
node -e "require('fs').writeFileSync('eas-project.json',JSON.stringify({projectId:process.argv[1]},null,2)+'\n')" ВАШ_PROJECT_ID
npx eas-cli@latest build --profile staging --platform android
```

- `ВАШ_PROJECT_ID` — на expo.dev, в настройках проекта.
- Аккаунт — **тот же**, которым собирали APK42: в нём лежит ключ подписи.
- **Не запускайте `eas init`** — он создаст новый проект с новым ключом, и
  APK не встанет поверх установленного.

EAS вернёт ссылку на готовый APK.

## 8. Что нужно изменить, чтобы в будущем собирал я

Один из вариантов:

1. **Открыть сеть до Expo.** В настройках окружения Claude Code разрешить
   `expo.dev` / `api.expo.dev` (или весь трафик) и дать мне токен Expo.
   Оговорка: смена сетевой политики обычно требует пересоздания окружения,
   то есть текущая сессия со всей историей оборвётся.
2. **Открыть SSH до Contabo** — разрешить исходящий порт 22 из моей среды и
   дать доступ к серверу. Тогда я выполню сборку там же, где вы её сейчас
   запускаете руками.

Ни то, ни другое не требуется прямо сейчас: сборка — разовая операция в одну
команду, а всё остальное уже готово.
