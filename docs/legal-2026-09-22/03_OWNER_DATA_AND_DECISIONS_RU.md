# Что нужно от владельца, чтобы документы стали документами

Редакция `1.0-draft-2026-09-22` — тексты пакета, исправленные по коду
22.09.2026 (что именно исправлено — `05_CORRECTIONS_REPORT_RU.md`). Всё,
что можно было взять из системы, взято из системы: сроки хранения, срок
бонусов, окно отложенных бонусов, порядок закрытия аккаунта, перечень
получателей данных, страны обработки. Осталось **17 полей**, и ни одно из
них не выводится из кода. Пока хотя бы одно из них пустое, публикационный
gate закрыт; сейчас он насчитывает **89 блокеров** — эти поля в пяти
документах на двух языках, метка «Проект для согласования» во всех десяти
текстах, отсутствие даты вступления и отсутствие утверждения.

Одна строка — одно поле. Рядом — откуда берётся ответ.

## A. Реквизиты компании (9 полей) — из учредительных документов

| Поле | Что вписать |
| --- | --- |
| `OPERATOR_LEGAL_NAME` | полное наименование юридического лица |
| `LEGAL_FORM` | организационно-правовая форма (ООО, ЗАО, ИП) |
| `REGISTRATION_NUMBER` | регистрационный номер |
| `TAX_ID` | УНН |
| `REGISTERED_ADDRESS` | юридический адрес |
| `SUPPORT_EMAIL` | адрес поддержки, который читает человек |
| `SUPPORT_PHONE` | телефон поддержки |
| `SUPPORT_HOURS` | часы работы поддержки |
| `PRIVACY_EMAIL` | адрес для обращений по данным (может совпадать с поддержкой) |

## B. Адрес публикации (1 поле)

`LEGAL_BASE_URL` — адрес, по которому документы доступны в браузере. Сейчас
API отдаёт их по `https://<домен API>/legal/documents/<ключ>?lang=ru`
в виде JSON и файла; для листингов в сторах и для ссылки в этом поле нужна
обычная HTML-страница — это отдельная небольшая работа, которая
делается после того, как поле получит значение.

## C. Поставщик хранилища фотографий (2 поля) — из договора с поставщиком

`MEDIA_STORAGE_PROVIDER`, `MEDIA_STORAGE_COUNTRY` — кто держит
S3-совместимое хранилище, к которому подключён сервис
(`MEDIA_STORAGE_S3_ENDPOINT` на Railway), и в какой стране. Я вижу, что
хранилище подключено, но не вижу чьё оно.

## D. Три срока и одно основание (4 поля) — владелец с юристом

| Поле | О чём | Что говорит код |
| --- | --- | --- |
| `FINANCIAL_RETENTION_BASIS` | ссылка на норму, по которой хранятся финансовые записи | код их не удаляет никогда; после закрытия аккаунта они обезличены |
| `SUPPORT_RETENTION` | сколько хранятся письма в ящике поддержки | вне системы — это ваш почтовый ящик |
| `BACKUP_RETENTION` | цикл перезаписи резервных копий Railway | мне политика копий недоступна; Railway её сообщает в настройках проекта |
| `TRANSFER_BASIS_SUMMARY` | основание передачи данных в США и Швейцарию | факт передачи установлен (Railway — Сан-Франциско, Expo — США, MapTiler — Швейцария); основание — вопрос юристу №11 |

## E. Дата вступления (1 поле) — при утверждении

`EFFECTIVE_DATE` — дата, с которой редакция действует. Ставится в момент
утверждения вместе с п. G.

## F. Что я записал в тексты из кода — проверьте, что это то, чего вы хотите

Эти значения взяты из настроек сервиса. Они верны для системы как она
есть; если вы хотите другие правила — менять надо и настройку, и текст,
и это ваше решение, а не моё:

| Положение в тексте | Значение | Где в коде |
| --- | --- | --- |
| Срок действия бонусов | 12 месяцев с начисления | `BONUS_EXPIRY_MONTHS`, по умолчанию 12 |
| Бонусы доступны через | 48 часов после начисления | `BONUS_PENDING_HOURS`, по умолчанию 48 |
| Порядок списания | сначала с ближайшим сроком сгорания | `bonus-engine.service.ts`, FIFO по `expiresAt` |
| Восстановленные при возврате | новое начисление с новым сроком 12 месяцев | `restoreSpentBonus` создаёт новый лот |
| Окно отложенных бонусов | 3 месяца, по истечении сгорают | `DEFERRED_BONUS_WINDOW_MONTHS`, по умолчанию 3 |
| Уровни приглашений | до трёх | `THREE_LEVEL_V2` |
| Закрытие аккаунта | обезличивание через 30 дней; бонусы сгорают | `ACCOUNT_DELETION_GRACE_DAYS`, по умолчанию 30 |
| Сессия входа | 30 дней | `JWT_REFRESH_EXPIRES_IN` |
| Сроки хранения записей | 30 / 90 / 90 / 90 / 180 дней | `RETENTION_*` |

Отдельно — «18 лет» в условиях: правило осталось из пакета, приложение
возраст не спрашивает. Оставлять его или убирать — вопрос юристу №4; если
оставлять, нужен третий пункт на форме регистрации.

## G. Утверждение редакции — только владелец

Два действия, без которых gate не откроется даже с заполненными полями:

1. Убрать из текстов строку «Проект для согласования» / «Համաձայնեցման
   նախագիծ» — это и есть акт утверждения текста.
2. Поставить в `apps/api/public/legal/documents/manifest.json`
   `"approvedByOwner": true` и `effectiveDate`, **и** задать на сервисе
   переменную `LEGAL_APPROVED_REVISION=1.0-draft-2026-09-22` (или новую
   строку редакции, если её переименуете).

Два подтверждения нарочно: правка файла в репозитории и переменная в
окружении — это две разные руки, и одной случайной правкой опубликовать
документы нельзя.

Пока редакция остаётся черновиком, тексты можно править сколько угодно —
архив следует за репозиторием. С момента утверждения он замораживается:
любое изменение уже утверждённого текста закрывает gate и требует **новой
редакции** (новый каталог `apps/api/public/legal/documents/<редакция>/` и
новая строка в `LEGAL_APPROVED_REVISION`), потому что открыть «именно ту
копию, которую приняли» иначе невозможно.

## Что произойдёт в приложении после утверждения

- документы станут видны всем, в том числе до входа;
- на экране регистрации появятся две обязательные галочки, и регистрация без
  них будет отклоняться, в том числе прямым вызовом API;
- старые сборки приложения, которые не умеют присылать согласия, перестанут
  регистрировать новых пользователей. Если это нежелательно на время
  раскатки, есть переменная `LEGAL_CONSENT_REQUIRED=false` — она **не**
  открывает публикацию, а только откладывает требование.
